## Hint 1
Keep the *runs* (start, end) per customer, not the days and not the events. A new day can only interact with the run that contains it or touches it on its left, and the run that starts right after it: at most two runs. Think about which of "day - 1" and "day + 1" belong to a run.

## Hint 2
If the runs are kept sorted by start, a binary search (`bisect`) finds the run with the greatest start `<= day` in O(log r). From that run and its successor you can classify the day: inside (duplicate), adjacent to the left run's end, adjacent to the right run's start, both (merge), or neither (insert a new run). Longest streak never decreases, so keep it as a running maximum instead of recomputing it.

## Hint 3
Work with `date.toordinal()` integers: `+1`/`-1` become plain arithmetic and nothing overflows at `date.max`. An alternative structure with no ordering at all is union-find over days (each root remembers the run's first and last day). For `current_streak`, locate the run with the greatest start `<= as_of`; if it ends before `as_of - 1` the answer is 0, and if it extends past `as_of` count only up to `as_of`.
