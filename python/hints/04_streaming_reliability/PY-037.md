## Hint 1
Hash a *structured* canonical form, not a joined string. A list of `[name, type_tag, text]` entries, serialised with a library that escapes everything (JSON), cannot be confused with a neighbouring field the way `"|".join(...)` can.

## Hint 2
Normalise each type to a text form that is equal exactly when the values should be equal: numbers by stripping trailing zeros of the `Decimal` and formatting without an exponent (zero special-cased; beware that `Decimal.normalize()` rounds to the 28-digit context precision, so `10**30` and `10**30 + 1` would collide), datetimes through `astimezone(timezone.utc)` and a fixed format with microseconds. Check `bool` before `int` and `datetime` before `date`, because of subclassing. The type tag keeps `True`, `1`, `"1"` and `b"1"` apart.

## Hint 3
Schema evolution falls out of one decision: skip entries whose value is `None` (or absent) instead of encoding them. Sort entries by field name so that the order of `fields` and of the record's keys is irrelevant, and reject duplicate names in `fields` before hashing.
