## Hint 1
First reduce the stream to what matters: per customer, the **set of distinct UTC dates** with a completed purchase. Duplicates, other statuses, guests and time-of-day all disappear in that step. Convert to UTC before taking the date.

## Hint 2
For one customer's dates, a run is a sequence where each date is exactly one day after the previous. If you sort the dates, a run ends where `date - previous_date != 1 day`. Use real date arithmetic (`timedelta`, or `date.toordinal()`), never month/day arithmetic by hand.

## Hint 3
Alternative without sorting: a date starts a run exactly when the previous calendar day is not in the set; from each such start, walk forward while the next day is in the set. Either way, keep **maximal** runs only, and filter by `min_days` at the end.
