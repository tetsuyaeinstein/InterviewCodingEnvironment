## Hint 1
Instead of "skip N rows", ask for "rows after the last one I gave you". That needs a position that is unique, so a timestamp alone is not enough: add the primary key as a tiebreaker.

## Hint 2
PostgreSQL can compare tuples: `(a, b) > (x, y)` follows the same lexicographic order as `ORDER BY a, b`. Whatever predicate you use must match the `ORDER BY` exactly.

## Hint 3
Ask for `page_size + 1` rows. If you get the extra one, there is a next page (drop the extra row and build the cursor from the last row you keep); if not, the cursor is `None`.
