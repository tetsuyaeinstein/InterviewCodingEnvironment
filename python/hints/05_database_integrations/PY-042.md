## Hint 1
In psycopg 3, `conn.cursor(name="some_unique_name")` returns a server-side cursor: the rows stay on the server and are pulled on demand. It needs a transaction around it.

## Hint 2
The cursor has an `itersize` attribute (rows per round trip when you iterate it), and `fetchmany(n)` pulls explicitly. Using the cursor as a context manager closes it on exit.

## Hint 3
`conn.transaction()` as a context manager gives you BEGIN/COMMIT around the whole thing, and rolls back (ending the transaction) when the generator is closed early, because `GeneratorExit` is raised at the `yield`.
