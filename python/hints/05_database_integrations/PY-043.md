## Hint 1
Collapse duplicates inside the input first (a dict keyed by business key), because PostgreSQL refuses an `INSERT ... ON CONFLICT DO UPDATE` that would touch the same row twice in one statement. Count what you drop.

## Hint 2
`INSERT ... ON CONFLICT (business_key) DO UPDATE SET ... WHERE target.seq < EXCLUDED.seq` only updates when the incoming row is newer. With `RETURNING`, rows that were skipped by the `WHERE` are simply not returned.

## Hint 3
To tell an insert from an update in `RETURNING`, the system column `xmax` is 0 for a freshly inserted row version. The table name goes through `psycopg.sql.Identifier`. `conn.transaction()` gives all-or-nothing behaviour. One statement per batch can pass whole columns as arrays (`unnest`), or you can use `executemany(..., returning=True)`.
