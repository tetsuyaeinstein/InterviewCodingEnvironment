# PY-002 · Completed spend per customer with exact cents

**Topic:** Python fundamentals · **Level:** easy · **Interview time:** ~15 min · **Module:** `python/practice/01_fundamentals/PY-002.py`

## Scenario

Finance reconciles kiosk revenue against the payment processor every night. They need **net
completed spend per customer**, accurate to the cent. Amounts arrive from several upstream
systems: some send `Decimal`, some send integers, and the CSV path sends strings such as
`"12.50"`. A rounding difference of one cent is a reconciliation break that someone has to
investigate by hand, so binary floating point is not acceptable anywhere in the pipeline.

## Function contract

```text
total_spend_by_customer(transactions: Iterable[Mapping[str, Any]],
                        include_guests: bool = False) -> dict[Any, Decimal]
```

Each transaction has (at least) the keys `customer_id`, `status` and `amount`.

- **Status filter:** only transactions whose `status` is `COMPLETED` count. The comparison
  ignores case and surrounding whitespace (`" completed "` counts). `None` or any other status
  (`PENDING`, `FAILED`, `REFUNDED`, ...) is ignored entirely; its amount is not even parsed.
- **Amounts** of counted transactions may be:
  - `Decimal`, used as is;
  - `int` (not `bool`), meaning whole currency units;
  - `str` holding a decimal number, surrounding whitespace allowed (`" 7.25 "`).

  A `float` or `bool` amount raises `TypeError`, and so does `None` or any other type. A string
  that is not a valid finite decimal number (`"abc"`, `""`, `"NaN"`) raises `ValueError`.
- Negative amounts (refunds/adjustments recorded as completed) are summed like any other amount.
- **Guests:** `customer_id` of `None` is a guest checkout. By default guests are excluded. With
  `include_guests=True`, their combined total appears under the key `None`.
- **Rounding:** sum the amounts **exactly** and round only the final total per customer to 2
  decimal places, with half-up rounding (`0.005` becomes `0.01`). Every value in the result
  must be a `Decimal` with exactly two decimal places (`Decimal("10.00")`, not `Decimal("10")`).
- A customer appears in the result if they have at least one counted transaction, even when the
  net total is `0.00`. Customers with no counted transaction do not appear.
- Return a plain `dict` (key order is not part of the contract). Do not mutate the input.

## Example

| customer_id | status | amount |
|---|---|---|
| 7 | COMPLETED | `"10.10"` |
| 7 | completed | `Decimal("0.20")` |
| 8 | PENDING | `"99.99"` |
| 8 | COMPLETED | `5` |
| None | COMPLETED | `"3.00"` |
| 9 | COMPLETED | `"4.00"` |
| 9 | COMPLETED | `"-4.00"` |

Result: `{7: Decimal("10.30"), 8: Decimal("5.00"), 9: Decimal("0.00")}`. With
`include_guests=True` the result also has `None: Decimal("3.00")`.

## Corner cases to think about

- Status values with odd casing and padding.
- Sub-cent amounts whose rounding depends on *when* you round.
- Amounts like `"0.015"` that a float cannot represent exactly.
- A customer whose purchases and refunds cancel out.
- Bad amounts on a non-completed transaction (they must not raise).

## Expected complexity

O(n) time in one pass; O(c) extra space for c customers.

## Clarify before you code

- Do refunds arrive as negative completed transactions, or as a separate status?
- Should guest revenue be reported, and under which key?
- What rounding mode does finance use, and at which step?
