# PY-009 · Event-type frequency report with normalisation

**Topic:** Python fundamentals · **Level:** easy · **Interview time:** ~10 min · **Module:** `python/practice/01_fundamentals/PY-009.py`

## Scenario

Kiosk firmware versions disagree on how they spell event types: `COIN_DEPOSIT`,
`coin_deposit`, `" Coin_Deposit\n"`, `"bill  jam"`. Some events arrive with no type at all.
Operations wants a daily **frequency table of event types**, most frequent first. It is pasted
into a report and diffed day over day, so the order must be **fully deterministic**.

## Function contract

```text
event_type_counts(events: Iterable[str | None]) -> list[tuple[str, int]]
```

- **Normalisation:** each event type becomes its canonical name as follows:
  1. strip leading/trailing whitespace (spaces, tabs, newlines, any Unicode whitespace);
  2. collapse every internal run of whitespace into a **single space**;
  3. lowercase it (`str.lower()`).

  Underscores and other characters are left alone.
- **Ignored:** `None`, and strings that are empty after stripping.
- Any other type (e.g. `int`, `bytes`) raises `TypeError`.
- **Output:** a list of `(name, count)` tuples, sorted by `count` **descending**, then `name`
  **ascending** (plain string order). Empty input (or nothing countable) returns `[]`.
- `events` may be a one-pass iterator.

## Example

Input: `["COIN_DEPOSIT", " coin_deposit ", "bill  jam", "Bill Jam", None, "", "door_open", "  ", "BILL\tJAM"]`

| name | count |
|---|---|
| `bill jam` | 3 |
| `coin_deposit` | 2 |
| `door_open` | 1 |

## Corner cases to think about

- Ties in count: alphabetical order, regardless of which appeared first.
- Tabs and newlines, inside and around names.
- All events ignored.
- A non-string value sneaking in.

## Expected complexity

O(n + u log u) for n events and u distinct names.

## Clarify before you code

- Are `coin_deposit` and `coin deposit` the same event? (Not under this contract: underscore
  vs space differ.)
- Should the report be truncated to the top N? (Not here.)
