# PY-003 · Top-K customers by spend with deterministic ties

**Topic:** Python fundamentals · **Level:** easy · **Interview time:** ~15 min · **Module:** `python/practice/01_fundamentals/PY-003.py`

## Scenario

Marketing sends a weekly "thank you" voucher to the **K highest-spending customers**. The list
is regenerated by a scheduled job, and the job is re-run whenever it fails. Two runs on the same
data **must** produce the same list. Otherwise a customer can get a voucher on Monday's run and
lose it on Tuesday's re-run, and support hears about it. There can be millions of customers, but
K is usually small (10 to 1,000).

## Function contract

```text
top_k_customers(spend: Mapping[int, Decimal], k: int) -> list[tuple[int, Decimal]]
```

- `spend` maps `customer_id` (int) to net spend (`Decimal`, possibly zero or negative, e.g.
  the output of PY-002).
- Return up to `k` `(customer_id, spend)` tuples, ranked by:
  1. spend **descending**;
  2. `customer_id` **ascending** on ties.
- If `k` is larger than the number of customers, return all of them, ranked.
- `k == 0` returns `[]`. A negative `k` raises `ValueError`.
- `k` must be an `int`. A `bool`, `float` or anything else raises `TypeError`.
- Ties are resolved strictly by the rule above. The result must not depend on the mapping's
  insertion order.
- Do not mutate `spend`.

## Example

`spend = {501: Decimal("80.00"), 502: Decimal("120.00"), 503: Decimal("80.00"), 504: Decimal("15.00"), 505: Decimal("120.00")}`

| k | result |
|---|---|
| 3 | `[(502, 120.00), (505, 120.00), (501, 80.00)]` |
| 4 | `[(502, 120.00), (505, 120.00), (501, 80.00), (503, 80.00)]` |
| 0 | `[]` |
| 10 | all five, ranked |

(Amounts shortened. The real values are `Decimal("120.00")` etc.)

## Corner cases to think about

- The K-th and (K+1)-th customers are tied: who gets in?
- Every customer has the same spend.
- Negative and zero spend.
- Empty mapping.
- The mapping is built in an order that differs from the tie-break order.

## Expected complexity

Aim for better than sorting everything when K is much smaller than n: **O(n log k)** time,
O(k) extra space. The tests use 300,000 customers. Any correct approach passes them, but be
ready to discuss the trade-off.

## Clarify before you code

- What happens on ties at the cut-off: include all tied customers (a "dense" top K) or exactly
  K? (Exactly K here, broken by customer id.)
- Are zero/negative spenders eligible? (Yes; the ranking simply puts them last.)
