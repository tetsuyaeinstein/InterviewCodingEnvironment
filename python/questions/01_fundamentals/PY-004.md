# PY-004 · Flatten nested transaction payloads into dotted keys

**Topic:** Python fundamentals · **Level:** medium · **Interview time:** ~25 min · **Module:** `python/practice/01_fundamentals/PY-004.py`

## Scenario

The kiosk API posts transactions as nested JSON: payment details, a list of line items, device
metadata. The landing zone stores them in a wide table whose columns are **flattened paths**
such as `payment.card.last4` and `items.0.sku`. The flattener runs on every message, so it must
be predictable:

- it must never silently overwrite a value;
- it must never mutate the caller's payload;
- it must survive hostile, extremely deep payloads.

## Function contract

```text
flatten_record(record: Mapping[str, Any], *, sep: str = ".",
               max_depth: int | None = None) -> dict[str, Any]
```

**Containers and leaves**

- Mappings (`dict` and other `Mapping`s) and sequences (`list`, `tuple`) are *containers*.
  Everything else is a *leaf*: `str`, `bytes`, `int`, `Decimal`, `bool`, `None`, `datetime`,
  etc. Strings are never split into characters.
- A mapping contributes its keys. A list/tuple contributes its indices `0, 1, 2, ...` as
  segments.
- Output keys are the path segments joined with `sep`: `{"payment": {"card": {"last4": "4242"}}}`
  becomes `{"payment.card.last4": "4242"}`.

**Empty containers and depth**

- An **empty** nested mapping is kept as a leaf with value `{}`, and an empty list/tuple as
  `[]`. Information is never dropped. A top-level empty record returns `{}`.
- `max_depth=None` means unlimited. With `max_depth=d`, output keys have **at most d
  segments**: a container that would need deeper keys is stored, unflattened, as the value of its
  d-segment key.
- `max_depth` must be `None` or a positive `int` (not `bool`); `sep` must be a non-empty `str`.
  Otherwise raise `ValueError`.

**Copies, keys and collisions**

- Container values placed in the output (empty containers, containers cut off by `max_depth`)
  must be **deep copies**. Mutating the output must never change the input. The input itself is
  never mutated.
- Every mapping key at every level must be a `str`. Otherwise raise `TypeError` (the top-level
  `record` must be a `Mapping`, also `TypeError`).
- **Collisions:** a literal key may contain `sep`, which is fine on its own (`{"a.b": 1}`
  becomes `{"a.b": 1}`). If two different paths produce the **same output key** (e.g.
  `{"a.b": 1, "a": {"b": 2}}`), raise `ValueError` naming the key. Never overwrite.
- **Order:** output keys appear in depth-first order following the input's own key/index order.
- Nesting can be much deeper than Python's recursion limit (the tests use 5,000 levels). The
  input is acyclic (JSON-like).

## Example

```text
{"id": "T-1",
 "payment": {"method": "card", "card": {"last4": "4242", "network": "VISA"}},
 "items": [{"sku": "COIN", "qty": 2}, {"sku": "GIFT", "qty": 1}],
 "tags": [],
 "meta": {}}
```

| output key | value |
|---|---|
| `id` | `"T-1"` |
| `payment.method` | `"card"` |
| `payment.card.last4` | `"4242"` |
| `payment.card.network` | `"VISA"` |
| `items.0.sku` | `"COIN"` |
| `items.0.qty` | `2` |
| `items.1.sku` | `"GIFT"` |
| `items.1.qty` | `1` |
| `tags` | `[]` |
| `meta` | `{}` |

With `max_depth=2`: `payment.card` maps to `{"last4": "4242", "network": "VISA"}` (a copy),
`items.0` maps to `{"sku": "COIN", "qty": 2}`, and so on.

## Corner cases to think about

- Lists of scalars, lists of lists, tuples.
- `None` values and empty strings as leaves.
- A key that contains the separator, with and without a real collision.
- Non-string keys (an integer key from a badly converted payload).
- 5,000-level-deep nesting.

## Expected complexity

O(total size of the input) time. Extra space proportional to the output plus the current depth.

## Clarify before you code

- What should happen on a key collision: overwrite, suffix, or fail?
- Are empty objects meaningful downstream, or can they be dropped?
- Is the result going to be "unflattened" again? If so, what makes the key scheme reversible?
