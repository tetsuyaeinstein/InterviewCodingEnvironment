# PY-022 · NDJSON reader with a quarantine for bad lines

**Topic:** ETL & file processing · **Level:** medium · **Interview time:** ~25 min · **Module:** `python/practice/03_etl_file_processing/PY-022.py`

## In plain words

> "A partner sends events as one JSON document per line, and some lines are broken. Pass the good records on, and put every bad line aside with enough detail to fix and replay it."

**You return:** `read_ndjson(lines, required_keys, quarantine)` returns an iterator of valid record dicts, in input order. Each bad line is appended to the `quarantine` list as a `Rejected`.

**The fine print, in short:**
- Blank lines are skipped silently. Otherwise the reasons, first match wins: `invalid_json`, `not_an_object`, `duplicate_key` (even nested), `missing_keys`. A key with value `null` counts as present.
- `line_number` is 1-based and counts blank lines. `raw` is the line minus its line ending. A BOM on line 1 is ignored; on later lines the line is `invalid_json`.
- Read lazily, one line at a time, and add to the quarantine as each line is read. Decimals stay exact (`0.1` is `Decimal`), and long lines are fine.

## Scenario

A partner ships clickstream events as newline-delimited JSON (one JSON document per line). Files
are large, and a few lines in every file are broken: truncated writes, arrays instead of
objects, events missing fields, the odd BOM from a Windows tool. The pipeline must **not crash
and must not silently drop data**. Good records flow on. Bad lines go to a **quarantine**
(dead-letter) with enough context to fix and replay them.

## Function contract

```text
read_ndjson(lines: Iterable[str], required_keys: Collection[str],
            quarantine: list[Rejected]) -> Iterator[dict]
```

`Rejected` is defined in the stub (frozen dataclass): `line_number`, `raw`, `reason`, `detail`.

**Laziness**

- It is a lazy iterator: it yields valid records **in input order** while reading.
- It consumes `lines` one at a time, so pulling the first record must not read the whole input.
- `lines` is any iterable of text lines, e.g. an open text file or a generator. Lines may end in
  `\n`, `\r\n` or nothing (the last line).

**Per-line rules**

| situation | outcome |
|---|---|
| empty or whitespace-only line | skipped silently, not quarantined |
| not valid JSON (truncated, trailing comma, single quotes, two documents on one line, `NaN` / `Infinity`, absurdly deep nesting, …) | `reason="invalid_json"` |
| valid JSON but not an object (array, number, string, `null`, `true`) | `reason="not_an_object"` |
| an object with the **same key twice** anywhere in it, including nested objects | `reason="duplicate_key"` |
| an object missing one or more `required_keys` | `reason="missing_keys"`; `detail` names the missing keys |
| otherwise | yielded |

When more than one rule applies, use the first matching row of the table.

**Field rules**

- `line_number` is the **1-based physical line number**, counting blank lines too.
- `raw` is the line with its trailing line terminator (`\r\n` / `\n`) removed and nothing else
  changed: leading and trailing spaces are kept.
- After a rejected line, **continue** with the next line. Append each `Rejected` to `quarantine`
  as soon as the line is read, not at the end.

**Parsing rules**

- A UTF-8 BOM (`﻿`) at the very start of **line 1** is ignored. A BOM on any later line makes
  that line `invalid_json`. It means two files were concatenated badly, and you shouldn't
  silently accept it.
- Whitespace around the JSON document on a line is allowed.
- A key that is present with value `null` counts as present.
- Numbers with a fraction or exponent are returned as `decimal.Decimal`: `0.1` stays exactly
  `0.1`, and `1e400` does not become infinity. Integers stay `int`.
- There is no limit on line length: a single line can be several MB.

## Example

Input lines:

| # | line |
|---|---|
| 1 | `{"id": "a", "v": 1.5}` |
| 2 | *(empty)* |
| 3 | `{"id": "b"` |
| 4 | `[1, 2]` |
| 5 | `{"v": 2}` |
| 6 | `{"id": "c", "id": "d"}` |
| 7 | `{"id": "e"}` |

With `required_keys=["id"]` it yields `{"id": "a", "v": Decimal("1.5")}` and `{"id": "e"}`.

The quarantine holds four entries:

- `(3, invalid_json)`
- `(4, not_an_object)`
- `(5, missing_keys, detail mentions "id")`
- `(6, duplicate_key)`

## Corner cases to think about

- Line numbers when blank lines are present.
- What the standard `json` module accepts by default that is not JSON.
- What it does silently with duplicate keys.
- A 100,000-deep `[[[[…]]]]` line.
- A file opened with `encoding="utf-8"` (not `utf-8-sig`) on Windows.

## Clarify before you code

- Is the quarantine a list, a file, or a topic? The interface is a caller-owned sink, so it can
  be swapped later.
- Should a quarantine threshold fail the job (e.g. > 1 % bad lines)? Not in this function, but
  have an opinion.

## Expected complexity

O(total bytes) time. Memory O(longest line + one record). Records are never accumulated.
