# PY-027 · Hive-style date partition paths for events

**Topic:** ETL & file processing · **Level:** easy · **Interview time:** ~15 min · **Module:** `python/practice/03_etl_file_processing/PY-027.py`

## In plain words

> "Before writing events to the lake, tell me which date folder each one belongs in, using the business day in a given time zone."

**You return:** `partition_records(records, *, ts_field="event_ts", tz="UTC", root="")` returns a dict of partition path like `year=2025/month=03/day=09` to the list of original records.

**The fine print, in short:**
- The day is the local calendar date in `tz`. A naive, missing, `None`, unparseable or non-datetime timestamp raises `ValueError`.
- Year is 4 digits, month and day are zero-padded, and separators are always `/`. If `root` is given, prefix it with exactly one `/`.
- Keys come out in ascending order, records stay in input order, and empty input gives `{}`.

## Scenario

Events land in a data lake laid out as `.../year=YYYY/month=MM/day=DD/part-*.parquet`, so that
query engines can prune partitions. Before writing, the job must decide which partition each
event belongs to.

The business day is defined in a **given time zone**: UTC for the global lake, `America/New_York`
for the US finance mart. Events come from many devices with assorted UTC offsets. A single event
filed under the wrong day is a reconciliation ticket.

## Function contract

```text
partition_records(records: Iterable[Mapping[str, object]], *, ts_field: str = "event_ts",
                  tz: str | tzinfo = "UTC", root: str = "") -> dict[str, list[Mapping]]
```

**Timestamps**

- `record[ts_field]` is an **aware** `datetime`, or an ISO-8601 string that
  `datetime.fromisoformat` parses **with** an offset (`Z`, `+09:00`, …).
- Raise `ValueError` for:
  - naive timestamps (no offset): never assume a zone;
  - a missing or `None` field;
  - an unparseable string;
  - any other type, such as epoch numbers.

**Partition key**

- `tz` is an IANA zone name (`"UTC"`, `"America/New_York"`) or a `tzinfo` object.
- Convert each timestamp to `tz`, then use the **local calendar date** there:
  `year=YYYY/month=MM/day=DD`.
- The year is 4 digits; month and day are 2 digits, all zero-padded. Example:
  `year=2025/month=03/day=09`.
- Separators are always `/`, on every OS. These are object-store keys, not OS paths.
- If `root` is non-empty, the key is `root` with trailing `/` removed, then `/`, then the
  partition path. Example: `s3://lake/events/` → `s3://lake/events/year=...`.

**Output**

- A dict `partition key -> list of records`.
- Keys are in **ascending** order.
- Each list holds the original record objects, unchanged, in **input order**.
- Empty input returns `{}`.

## Example

| id | event_ts | partition (tz = UTC) |
|---|---|---|
| 7 | `2026-01-31T22:30:00-03:00` | `year=2026/month=02/day=01` |
| 8 | `2026-02-01T07:00:00+09:00` | `year=2026/month=01/day=31` |
| 9 | `2026-01-31T12:00:00Z` | `year=2026/month=01/day=31` |

Result: `{"year=2026/month=01/day=31": [rec8, rec9], "year=2026/month=02/day=01": [rec7]}`

## Corner cases to think about

- `23:59:59.999999` vs `00:00:00`.
- A negative offset late in the evening, which is already tomorrow in UTC.
- The New York day around a DST change.
- Running the job on Windows (path separators).
- Year 999.

## Expected complexity

O(n) to group, plus sorting the (few) partition keys.
