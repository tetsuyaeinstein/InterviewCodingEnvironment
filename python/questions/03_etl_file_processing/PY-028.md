# PY-028 · Reconcile two extracts with canonical row hashes

**Topic:** ETL & file processing · **Level:** hard · **Interview time:** ~40 min · **Module:** `python/practice/03_etl_file_processing/PY-028.py`

## Scenario

You are migrating the `accounts` table from an on-prem database to the cloud warehouse. Every
night, an extract from the old system (**source**) and one from the new system (**target**) must
be reconciled by business key. The report has three parts:

- keys **missing** from the target;
- **extra** keys in the target;
- keys whose rows **changed**, and which fields differ.

The two systems serialise values differently:

- `1.0` vs `1.00`;
- columns in a different order;
- NULLs either omitted or written explicitly.

The comparison must ignore those cosmetic differences but **never** confuse real ones. NULL vs
`""` vs the text `"NULL"` are three different values.

## Function contract

```text
canonical_row_hash(row: Mapping[str, object], *, exclude: Collection[str] = ()) -> str
diff_streams(source: Iterable[Mapping], target: Iterable[Mapping], key_fields: Sequence[str], *,
             exclude: Collection[str] = ()) -> DiffResult
```

`DiffResult(missing, extra, changed, unchanged)` is defined in the stub.

### Canonical form (the policy, which both functions must follow)

| rule | meaning |
|---|---|
| field order | irrelevant |
| `exclude` | the named fields are ignored entirely (e.g. `loaded_at`) |
| NULL | `None` and an **absent** field are the same thing. `""`, `"NULL"`, `"None"` and `" "` are ordinary, distinct strings. |
| numbers | `int` and `Decimal` compare **by numeric value**: `1 == Decimal("1.0") == Decimal("1.00")`, and `Decimal("-0.00") == 0`. `Decimal` NaN/Infinity → `ValueError`. |
| booleans | a separate type: `True` ≠ `1` ≠ `"1"` ≠ `"true"` |
| strings | compared exactly: case, whitespace and code points all count, with no Unicode normalisation |
| other types | including `float`, lists and dicts → `TypeError`. Floats must be converted deliberately upstream. |

**`canonical_row_hash`**

- Returns the **SHA-256 hex digest** (64 lowercase hex characters) of an encoding of the
  canonical form.
- Two rows must get the same hash **if and only if** they are canonically equal (ignoring
  SHA-256 collisions).
- The encoding is up to you, but it must be **unambiguous**. Values containing `|`, `,`, `=`,
  `:`, quotes or NUL characters, and field names that run into values, must never make two
  different rows encode identically.

### `diff_streams`

- `key_fields` define the business key: `tuple(row[f] for f in key_fields)`.
- A missing or `None` key value → `ValueError`.
- A key that occurs **twice within one stream** → `ValueError`.
- Inputs can be one-shot iterators in any order.

**Report fields**

| field | content |
|---|---|
| `missing` | sorted list of keys present in source but not in target |
| `extra` | sorted list of keys present in target but not in source |
| `changed` | sorted list of `(key, fields)` for keys on both sides whose rows are not canonically equal. `fields` is the sorted tuple of field names whose canonical values differ, across the union of both rows' non-excluded fields. A field absent on one side and `None` on the other does **not** differ. |
| `unchanged` | count of keys on both sides that are canonically equal |

## Example

| side | id | name | amt | note |
|---|---|---|---|---|
| source | 7 | Ida | `Decimal("3.10")` | `None` |
| target | 7 | Ida | `Decimal("3.1")` | *(absent)* |
| source | 8 | Max | `Decimal("2.00")` | `""` |
| target | 8 | Max | `Decimal("2.00")` | `None` |
| target | 9 | Lou | `Decimal("1")` | |

Result:

- `missing=[]`
- `extra=[(9,)]`
- `changed=[((8,), ("note",))]`
- `unchanged=1`

## Corner cases to think about

- `"|".join(values)` makes `("a|b", "c")` and `("a", "b|c")` look the same.
- `str(Decimal("1.0")) != str(Decimal("1.00"))`, but `str(True) == "True"`.
- One side omits NULL fields entirely.
- Duplicate keys in an extract usually mean a broken join upstream: refuse to produce a diff.

## Clarify before you code

- Should trailing whitespace or case be ignored? Here: no. That is a separate, explicit
  normalisation step.
- Numeric policy: by value, or by value and scale? Here: by value. Be ready to argue the other way.

## Expected complexity

- O(n + m) hashing work, plus sorting of the report.
- State how much memory your approach needs, and how you would reconcile 2 billion rows per side.
- The tests reconcile 100,000 rows per side in a few seconds.
