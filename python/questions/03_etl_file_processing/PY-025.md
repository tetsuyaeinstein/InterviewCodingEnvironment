# PY-025 · Single-pass column profile for data-quality checks

**Topic:** ETL & file processing · **Level:** medium · **Interview time:** ~30 min · **Module:** `python/practice/03_etl_file_processing/PY-025.py`

## In plain words

> "Before we onboard a new source, profile each column: nulls, distinct values, range, average, most common values, and whether it mixes types. You only get one pass over the rows."

**You return:** `profile_columns(rows)` returns a dict of column name to `ColumnProfile`, in first-seen column order.

**The fine print, in short:**
- Only `None` is null; `""` is a value. A column missing from a row counts as null for that row, even before it first appeared.
- Numbers compare by value across int, float and Decimal, but different types are never equal (`True` is not `1`, `"1"` is not `1`). `min`, `max` and `mean` follow the type rules in the spec.
- Top values: up to 3, highest count first, ties go to whichever appeared first. Empty input gives `{}`.

## Scenario

Before a new source is onboarded, the data-quality team wants a quick **profile of every column**:
how many NULLs, how many distinct values, the range, the average for numeric columns, the most
common values, and whether a column holds **more than one type** (the classic "`'10'` and `10` in
the same field" problem).

The rows come from a database cursor or a decoded file stream. You get **one pass**, and the
iterable cannot be rewound.

## Function contract

```text
profile_columns(rows: Iterable[Mapping[str, object]]) -> dict[str, ColumnProfile]
```

`ColumnProfile` is defined in the stub. Return a dict `column name -> ColumnProfile`, with columns
in **first-seen order** across all rows.

**Input**

- Values are `None`, `bool`, `int`, `float`, `Decimal`, `str`, `date` or `datetime`.
- Datetimes in one column are either all aware or all naive.
- There are no NaN values.
- A column missing from a row counts as **NULL** for that row. This includes rows *before* the
  column first appeared.
- Only `None` is NULL. `""` is a value.

**Type names**

| Python type | type name |
|---|---|
| `bool` | `bool` (never `int`) |
| `int` | `int` |
| `float`, `Decimal` | `decimal` |
| `str` | `str` |
| `datetime` | `datetime` (never `date`) |
| `date` | `date` |

**Fields**

| field | meaning |
|---|---|
| `count` | total number of rows |
| `null_count` | rows where the column is NULL or missing |
| `types_seen` | sorted tuple of the type names of the non-NULL values |
| `inferred_type` | `"null"` if there are no non-NULL values; the single type name if there is one; `"decimal"` when the types are exactly `int` + `decimal` (numeric widening); otherwise `"mixed"` |
| `distinct_count` | exact number of distinct non-NULL values. Numbers are compared **by value** across int/float/Decimal (`1`, `1.0`, `Decimal("1.00")` are one value). Values of different type names are always distinct (`True` ≠ `1`, `"1"` ≠ `1`). |
| `min`, `max` | over non-NULL values when `inferred_type` is not `"mixed"` / `"null"`; otherwise `None`. They return the original values. |
| `mean` | only when `inferred_type` is `"int"` or `"decimal"`: an **exact `Decimal`**, the sum of the values (floats converted via `Decimal(repr(x))`) divided by the non-NULL count, in the default decimal context. Otherwise `None`. |
| `top_values` | up to 3 `(value, count)` pairs of the most frequent non-NULL values, using the same identity as `distinct_count`. Ordered by count descending; **ties go to the value whose first occurrence came first**. The value shown is the first-seen representative. |

Empty input returns `{}`.

## Example

Rows:

- `{"sku": "A", "qty": 2}`
- `{"sku": "B", "qty": None}`
- `{"sku": "A", "qty": "3"}`

| column | null_count | distinct | min / max | mean | top_values | inferred / types_seen |
|---|---|---|---|---|---|---|
| sku | 0 | 2 | `"A"` / `"B"` | `None` | `[("A", 2), ("B", 1)]` | `str` / `("str",)` |
| qty | 1 | 2 | `None` / `None` | `None` | `[(2, 1), ("3", 1)]` | `mixed` / `("int", "str")` |

## Corner cases to think about

- `isinstance(True, int)` is `True`, and `datetime` is a subclass of `date`.
- `True == 1` and `hash(True) == hash(1)`: a plain `Counter` merges them.
- `min()` over `[10, "10"]` raises `TypeError`, possibly halfway through the stream.
- Float accumulation drifts: `0.1 + 0.1 + 0.1 != 0.3`.

## Expected complexity

- One pass: time O(rows × columns).
- Memory O(Σ distinct values): exact distinct counts need it. Be ready to discuss approximate
  alternatives for huge cardinalities.
- The tests profile 150,000 rows from a generator in a few seconds.
