# PY-021 · Streaming customer spend from a CSV export

**Topic:** ETL & file processing · **Level:** medium · **Interview time:** ~25 min · **Module:** `python/practice/03_etl_file_processing/PY-021.py`

## In plain words

> "Here is a nightly transactions CSV, several GB. Give me the total completed spend per customer, exact to the cent, without loading the file into memory."

**You return:** `spend_per_customer(source, *, guest_key=None)` returns a dict of customer id string to `Decimal` total. `source` is a path or an iterable of text lines.

**The fine print, in short:**
- Only `COMPLETED` rows count (stripped, any case). Amounts of other rows are never parsed. A counted row with a bad amount raises `ValueError`.
- Columns are matched by name in any order. A missing or duplicated required column, an empty input, or a row with the wrong field count raises `ValueError`. Quoted fields and a BOM must work.
- Customer ids are kept as strings (`"007"` is not `"7"`). Blank ids are guests: excluded, or totalled under `guest_key` if given.

## Scenario

The payments platform drops a nightly CSV export of transactions. Finance wants **total completed
spend per customer**. The file is several GB, so you can't hold it in memory. It comes from a
system that writes free-text notes, so expect quoted commas, quotes and even newlines inside
fields. It is sometimes produced on Windows, with a UTF-8 BOM and CRLF line endings. Money must
be exact.

## Function contract

```text
spend_per_customer(source: str | os.PathLike | Iterable[str], *,
                   guest_key: str | None = None) -> dict[str, Decimal]
```

**Input**

- `source` is either:
  - a **path** (`str` or `PathLike`): open it yourself as UTF-8 and close it when done; or
  - an **iterable of text lines**, e.g. a file the caller opened with `newline=''`, or a
    generator. Do not close it. It may be consumable only once, and it has no `read()` or
    `readlines()`.
- A UTF-8 **BOM** in front of the first header name must be ignored, whichever kind of source it is.

**Header**

- The first record is the header. Column names are matched after stripping surrounding
  whitespace, and matching is **case-sensitive**.
- Columns may appear in **any order**, and extra columns are allowed.
- Required columns: `customer_id`, `amount`, `status`.
- Raise `ValueError` if:
  - a required column is missing;
  - a required column appears **more than once** (ambiguous);
  - the input is completely empty (no header).

**Rows**

- Fields follow standard CSV quoting: commas, doubled quotes and newlines inside a quoted field
  belong to the field.
- Lines that are empty or contain only whitespace are skipped.
- Any other row whose field count differs from the header's → `ValueError`. Mention the line in
  the message.
- A row counts only if `status`, stripped and compared case-insensitively, equals `COMPLETED`.
  So `COMPLETED_REVERSED` does not count.
- **Amounts of rows that don't count are never parsed**, so garbage there is harmless.
- For counted rows, `amount` (stripped) must parse as a finite `Decimal`. Otherwise → `ValueError`.
  This includes empty, `NaN` and `Infinity`.
- Negative amounts are added as they are.
- Keep exact `Decimal` arithmetic, with no rounding: `0.10 + 0.10 + 0.10` is `Decimal("0.30")`.

**Customers**

- The `customer_id` value is stripped and used **as a string**: `"007"` and `"7"` are different
  customers.
- **Guest rows** have an empty or whitespace-only `customer_id`:
  - with `guest_key=None` (the default) they are excluded;
  - otherwise they are totalled under the key `guest_key`.
- A customer appears in the result only if at least one of their rows counted. A total of `0`
  is kept.

**Output:** a dict `customer_id -> Decimal total`, in any order.

## Example

| customer_id | amount | status |
|---|---|---|
| K9 | 12.50 | COMPLETED |
| K9 | 99.00 | PENDING |
| `""` | 3.00 | COMPLETED |
| K2 | -1.25 | completed |

Result: `{"K9": Decimal("12.50"), "K2": Decimal("-1.25")}`. With `guest_key="GUEST"` there is
also `"GUEST": Decimal("3.00")`.

## Corner cases to think about

- A quoted note such as `"refund, see ""ticket"" 12\n2nd line"`: one record that spans two
  physical lines.
- BOM + CRLF.
- Trailing blank lines.
- A header with padded names.
- A `PENDING` row whose amount is `n/a`.
- A file of 10 GB: memory must not grow with the number of rows.

## Clarify before you code

- What exactly is a guest? What should happen to guest spend?
- Fail fast on a bad amount, or skip it? This contract says fail, because silently dropping
  money is worse than a failed job.
- Do status values vary in case or padding?

## Expected complexity

One pass. Time O(rows). Memory O(distinct customers): the tests stream 200,000 rows through a
generator under a memory budget.
