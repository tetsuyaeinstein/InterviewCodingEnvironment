# PY-045 · A testable extract / transform / load pipeline

**Topic:** PostgreSQL, APIs & backend patterns · **Level:** medium · **Interview time:** ~30 min · **Needs:** nothing external (pure Python with fakes)

## Scenario

Your team has five small ingestion jobs that all look the same: read records, clean them, write
them in batches. Each job reimplements batching and error handling differently, and none can be
tested without a database. You are asked to write the shared runner, with the source, the
transformation and the sink **injected**, so unit tests use in-memory fakes and production plugs in
a database loader.

## Contract

```text
run_etl(extract, transform, load, *, batch_size: int = 100, on_error: str = "quarantine") -> RunSummary
```

- `extract()` returns an iterable of records. It may be a **generator over a huge source**: never
  materialize it, and call `extract` exactly once.
- `transform(record)` returns the row (a dict) to load, or `None` to **filter the record out**.
  It may raise any `Exception` for a bad record.
- `load(batch)` receives a non-empty `list[dict]` and returns nothing. It is **atomic**: if it raises,
  none of that batch was stored. `load` is never called with an empty list.
- Rows are loaded **in source order**, in batches of exactly `batch_size`, except the last batch,
  which may be smaller. A batch is loaded **as soon as it is full** (the runner must not read ahead
  of a full batch).

### Error handling (`on_error`)

- `"quarantine"` (default):
  - A record whose `transform` raises `Exception` is recorded as `Quarantined(position, "transform", "<Type>: <msg>", record)`
    and the run continues.
  - If `load(batch)` raises `Exception`, retry **each row of that batch alone**
    (`load([row])`) in order. Rows that succeed count as loaded; rows that still raise are quarantined as
    `Quarantined(position, "load", "<Type>: <msg>", row)`. One poison row must not lose its neighbours.
- `"raise"`: the first error from `transform` or `load` propagates **unchanged**, immediately. Batches
  already loaded stay loaded; the pending (not yet loaded) rows are not loaded.
- Any other `on_error` value raises `ValueError` before anything is read. `batch_size < 1` also raises `ValueError`.
- An exception from `extract` itself (including during iteration) propagates in both modes; earlier
  full batches stay loaded.
- Only `Exception` is handled. `KeyboardInterrupt` and other `BaseException`s always propagate.

### Summary

`RunSummary` fields: `read` (records pulled from the source), `filtered`, `loaded`, `batches`
(number of `load` calls for regular batches, not counting single-row retries) and `quarantined`
(in position order). Invariant: `read == filtered + loaded + len(quarantined)`.

`position` is the 0-based index of the record in extraction order (counting every record,
including filtered ones).

## Example (made-up)

Source `[1, 2, "x", 4, 5]`, transform `{"id": int(r)}` (raises `ValueError` on `"x"`), `batch_size=2`:
`load` receives `[{"id": 1}, {"id": 2}]`, then (the bad record having been quarantined as position 2)
`[{"id": 4}, {"id": 5}]`. Summary: `read=5`, `loaded=4`, `batches=2`, one quarantined entry.

## Corner cases

- Empty source: no `load` call, zero summary.
- Source size is an exact multiple of `batch_size`: no empty trailing batch.
- Every record filtered or quarantined.
- A batch with one bad row in the middle (only that row is quarantined).
- A sink that rejects every row.
- Running the same pipeline twice into an idempotent sink (keyed upsert) gives the same sink state.

## Expected complexity

O(n) time, O(batch_size) memory.
