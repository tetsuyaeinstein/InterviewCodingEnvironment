# PY-044 · Keyset pagination with a stable composite cursor

**Topic:** PostgreSQL, APIs & backend patterns · **Level:** medium · **Interview time:** ~25 min · **Needs:** running lab PostgreSQL (`requires_postgres`)

## In plain words

> "An API lists a store's transactions page by page while new data keeps arriving. Page 50,000 must cost the same as page 1, and many rows share a timestamp, so nothing may be skipped or repeated."

**You return:** `fetch_page(conn, store_id, start, end, cursor=None, page_size=100)` returns `(rows, next_cursor)`, where `next_cursor` is `(transaction_ts, transaction_id)` of the last row returned, or `None` when no rows follow.

**The fine print, in short:**
- Scope: that store, UTC date in `[start, end)`. Order by `transaction_ts`, then `transaction_id`. A cursor means rows strictly after that position (it need not match a real row). A last page that is exactly full also returns `None`.
- `page_size` must be 1..1000 and a malformed cursor raises `ValueError`. No `OFFSET`. An empty scope returns `([], None)`.
- Guest rows have `customer_id` `None`. Do not commit or close the connection.

## Scenario

An internal API exposes a store's transactions page by page. Clients walk the whole list while new
data keeps arriving, and some tables hold hundreds of millions of rows, so page 50,000 must be as
cheap as page 1. Many transactions share the same timestamp (tills batch-post), so a timestamp
alone cannot identify a position in the list.

## Function contract

```text
Cursor = tuple[datetime, int]      # (transaction_ts, transaction_id) of the last row already served

fetch_page(conn, store_id: int, start: date, end: date,
           cursor: Cursor | None = None, page_size: int = 100) -> tuple[list[dict], Cursor | None]
```

- Scope: rows of `transactions` with `store_id = store_id` and **UTC business date** in
  `[start, end)` (half-open, `end` exclusive).
- Order: `transaction_ts`, then `transaction_id`. This order is total, so it is stable.
- `cursor=None` returns the first page. Otherwise return the rows that come **strictly after**
  the position `(ts, id)` in that order. The cursor does not need to refer to an existing row.
- Each row is a dict with exactly: `transaction_id`, `customer_id` (int or `None` for guests),
  `transaction_ts` (aware `datetime`), `gross_amount` (`Decimal`), `transaction_status`.
- Return at most `page_size` rows and `next_cursor`: the position of the **last row returned**, or
  `None` when there are no further rows. A final page that happens to be exactly full must also
  return `None` (no trailing empty page).
- An empty scope returns `([], None)`.
- `page_size` must be between 1 and `MAX_PAGE_SIZE` (1000); otherwise `ValueError`.
- A malformed cursor (not a 2-tuple, a naive timestamp, a non-int id) raises `ValueError`.
- **No `OFFSET`.** The cost of a page must not grow with its distance from the start. All values
  are bind parameters. Do not commit or close the connection.

## Example (made-up numbers)

Rows in scope in order: `(10:00, 7)`, `(10:00, 9)`, `(10:00, 12)`, `(10:05, 3)`.
With `page_size=2`: page 1 holds ids 7, 9 and `next_cursor = (10:00, 9)`; page 2 holds ids 12, 3 and
`next_cursor = None`. Pages concatenated equal the full ordered result: no duplicates, no gaps.

## Corner cases

- Several rows with the same timestamp straddling a page boundary (customer 26's two sales at
  one instant; the six identical-time rows of customer 64; the guest pair 9801/9802).
- Guest rows (`customer_id` NULL).
- A cursor that points between two rows, or after the last row.
- `page_size = 1`, and `page_size` equal to the number of rows.

## Expected complexity

Each call is one index range scan that reads `page_size + 1` rows. State the index you would
want for this access path.
