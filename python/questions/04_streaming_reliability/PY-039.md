# PY-039 · Exact duplicate messages versus conflicting payloads for one ID

**Topic:** Streaming & reliability · **Level:** easy · **Interview time:** ~20 min · **Module:** `python/practice/04_streaming_reliability/PY-039.py`

## Scenario

Your ingestion job reads a batch of messages from an at-least-once queue. Every message has a
`message_id` assigned by the producer. Seeing the same id twice is normal: redelivery after a
timeout. Seeing the same id with **different content** is not: the producer reused an id, or two
systems collided. Redelivered copies can be harmlessly dropped; conflicts must be quarantined and
investigated.

Before loading the batch, classify it into three groups.

## Function contract

```text
classify_messages(messages: Iterable[tuple[str, Mapping]]) -> Classification
```

`Delivered(message_id, payload, deliveries)`, `Conflict(message_id, payloads, deliveries)` and
`Classification(unique, exact_duplicates, conflicts)` are defined in the stub. `messages` may be
a one-shot iterator.

| list | contains one entry per `message_id` that was... |
|---|---|
| `unique` | seen **exactly once** |
| `exact_duplicates` | seen **two or more times**, all with the same canonical payload. `deliveries` is the number of times seen |
| `conflicts` | seen with **two or more distinct** canonical payloads (any number of deliveries). `payloads` holds one payload per distinct canonical form in **first-arrival order**; `deliveries` is the total count |

- `Delivered.payload` is the **first-arriving** payload of that id (as a `dict`).
- All three lists are sorted by `message_id`.
- Results must not depend on the order of messages, except for which payload is "first" and
  the order of `Conflict.payloads`.
- Invalid input: `message_id` not a non-empty `str` → `ValueError`; payload not a `Mapping`, a non-`str`
  key, or an unsupported value type (e.g. `set`, `bytes`, `datetime`) → `TypeError`.

### When are two payloads "the same"? (canonical comparison)

| aspect | rule |
|---|---|
| key order (at any depth) | irrelevant |
| list order | **relevant**; `tuple` is treated like `list` |
| numbers | by **value** across `int`, `float` and `Decimal`: `1 == 1.0 == Decimal("1.00")`. A `float` counts as its shortest round-trip decimal text, so `0.1 == Decimal("0.1")`. `0.0 == -0.0 == 0`. `NaN` equals `NaN` |
| `bool` | a separate type: `True` is **not** `1` |
| strings | exact; `"1"` is not `1` |
| `None` vs a missing key | **different**: `{"a": None}` ≠ `{}` |
| nested dicts/lists | compared recursively under the same rules |

## Example

| arrival | message_id | payload |
|---|---|---|
| 1 | m1 | `{"amount": Decimal("10.0"), "ccy": "EUR"}` |
| 2 | m2 | `{"qty": 1}` |
| 3 | m1 | `{"ccy": "EUR", "amount": 10}` |
| 4 | m3 | `{"qty": 5}` |
| 5 | m3 | `{"qty": 6}` |

Result: `unique = [m2]`; `exact_duplicates = [m1 (payload from arrival 1, deliveries 2)]`;
`conflicts = [m3 with payloads ({"qty": 5}, {"qty": 6}), deliveries 2]`.

## Corner cases to think about

- `Decimal("1.0")`, `1`, `1.0`; `True` and `1`; `0.1` and `Decimal("0.1")`.
- Key order differences in nested dicts; the same list in a different order.
- Three deliveries: A, A, B (conflict with 3 deliveries) and A, B, A.
- Payloads containing lists and dicts are unhashable: you cannot put them in a `set`.
- 100,000 messages with nested payloads: no pairwise comparison.

## Clarify before you code

- What exactly makes two messages "the same"? Envelope metadata (delivery attempt, timestamps) is not payload.
- Should numeric representation differences between producers count as a conflict?
- Who owns a conflict: drop both, keep the first, or park for a human?

## Expected complexity

O(total payload size) time with a single pass. The tests use 100,000 messages with nested payloads (< 6 s).
