# PY-037 · Null-safe canonical record fingerprint that survives schema evolution

**Topic:** Streaming & reliability · **Level:** easy · **Interview time:** ~20 min · **Module:** `python/practice/04_streaming_reliability/PY-037.py`

## In plain words

> "I need a fingerprint for a business record, so we can tell cheaply whether a re-delivered row really changed. Two different records must not collide, and adding a new empty column must not change old fingerprints."

**You return:** `fingerprint(record, fields)` returns a 64-character lowercase SHA-256 hex string of the record restricted to `fields`.

**The fine print, in short:**
- `None` and an absent key are the same and contribute nothing; `""`, `"None"` and `" "` are ordinary, distinct strings. Order of `fields` or keys does not matter; duplicate fields raise `ValueError`.
- `int` and `Decimal` compare by value; `bool`, `bytes` and `date` are their own types; aware datetimes compare by instant (naive raises `ValueError`); NaN/Infinity raise `ValueError`; `float`, `list`, `dict` raise `TypeError`.
- Two inputs share a digest if and only if their canonical forms are equal.

## Scenario

Your CDC pipeline stores a **fingerprint** of every business record to decide cheaply whether a
re-delivered row actually changed (skip the write when the fingerprint matches). Two bugs have
already hurt you:

1. `"|".join(values)` made `("ab", "c")` and `("a", "bc")` collide, and `None`, `""` and the text
   `"None"` all became the same thing;
2. when the team added a nullable `loyalty_tier` column, **every** stored fingerprint changed,
   the whole table looked "modified" and a 400 GB merge ran at 2 a.m.

Write one fingerprint function that has neither problem.

## Function contract

```text
fingerprint(record: Mapping[str, object], fields: Sequence[str]) -> str
```

Returns the **SHA-256** hex digest (64 lowercase hex characters) of a canonical encoding of the
record **restricted to `fields`**. The encoding itself is up to you. The tests check *properties*:
two inputs get the same digest **if and only if** their canonical forms are equal.

### Canonical form

| aspect | rule |
|---|---|
| which fields | only those named in `fields`; other keys in `record` (e.g. `loaded_at`) are ignored |
| order | neither the order of `fields` nor the order of keys in `record` matters |
| duplicates in `fields` | `ValueError` |
| NULL | `None` and an **absent** key are the same thing, and contribute **nothing** to the canonical form |
| strings | `""`, `"None"`, `"null"`, `" "` are ordinary, distinct, non-NULL strings. Compared exactly (case, whitespace, no Unicode normalisation) |
| numbers | `int` and `Decimal` compare **by value**: `1`, `Decimal("1")`, `Decimal("1.00")`, `Decimal("0.1E+1")` are equal; `0`, `-0`, `Decimal("0.00")` are equal. NaN/Infinity → `ValueError` |
| booleans | their own type: `True` differs from `1` and from `"True"` |
| `bytes` | their own type: `b"a"` differs from `"a"` |
| `datetime` | must be timezone-aware (naive → `ValueError`); equal **instants** are equal whatever the offset, to microsecond precision |
| `date` | its own type: `date(2025,1,2)` differs from the midnight `datetime` and from `"2025-01-02"` |
| anything else | including `float`, `list`, `dict` → `TypeError` |

### Schema evolution

Because NULL contributes nothing, appending a new field to `fields` whose value is `None`/absent in
a record **does not change that record's fingerprint**. Giving it any real value does.

## Example

| record | fields | notes |
|---|---|---|
| `{"id": 7, "name": "Ida", "tier": None}` | `["id", "name", "tier"]` | same digest as the next two |
| `{"name": "Ida", "id": Decimal("7.0")}` | `["name", "id", "tier"]` | key order, `Decimal` vs `int`, absent vs `None` |
| `{"id": 7, "name": "Ida"}` | `["id", "name"]` | the schema before `tier` existed |

## Corner cases to think about

- Values containing `|`, `,`, `=`, `:`, quotes, newlines or NUL characters; field **names** that look like values.
- A field named like another field's value (`{"a": "b"}` versus `{"b": "a"}`).
- `str(Decimal("1.0")) != str(Decimal("1.00"))`.
- `datetime(...).isoformat()` differs by offset for the same instant.
- Large integers; non-ASCII text (`é` as one code point vs two).

## Clarify before you code

- Should `""` and NULL be equal? (Here: no, because Oracle-style "empty is NULL" is a source quirk, not a default.)
- Should the fingerprint also encode a *version* of the policy, so that you can migrate it later?
- Is 128-bit (or 64-bit) hashing enough at your volume? What is the collision probability for 10^10 rows?

## Expected complexity

O(size of the selected values + f log f) per record, one pass.
