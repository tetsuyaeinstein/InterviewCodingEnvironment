# PY-020 · Customer purchase streaks (pure Python)

**Topic:** algorithms & interview patterns · **Level:** hard · **Interview time:** ~30 min · **Module:** `python/practice/02_algorithms/PY-020.py`

## Scenario

The loyalty team rewards "habit" customers: anyone who bought on **five or more consecutive
calendar days**. The same question exists as a SQL exercise (SQL-021); here the data arrives as
a stream of purchase records in a Python job, for example while a file is being loaded, and you
must answer it without a database. The job is re-run on the same files, so the output must be
fully deterministic. In production there are hundreds of millions of records.

## Function contract

```text
find_purchase_streaks(
    records: Iterable[tuple[int | None, datetime, str]],
    min_days: int = 5,
) -> dict[int, list[tuple[date, date, int]]]
```

Each record is `(customer_id, purchased_at, status)`.

**Which records count**

- Only `status == "COMPLETED"` records count (exact, case-sensitive string comparison).
  Every other status, such as `"CANCELLED"` or `"PENDING"`, is ignored as if the row were absent.
- Records with `customer_id is None` (guest checkouts) are ignored.
- `purchased_at` is a **timezone-aware** `datetime` (any offset). The **business date** is its
  **UTC calendar date**. A naive `datetime` raises `ValueError`.
- Several purchases by one customer on the same business date count as **one** purchase day.

**What is a streak**

- A streak is a **maximal** run of consecutive business dates (each date is exactly one day after
  the previous) that all have a counted purchase. A run of 7 days is one streak of length 7, not
  several streaks of 5.
- Only streaks with length `>= min_days` are reported.
- `min_days` must be an `int`. A `bool`, `float` or other type raises `TypeError`. A value below 1
  raises `ValueError`. Validate it before reading the records.

**Result**

- A `dict` that maps `customer_id` to the list of that customer's reported streaks.
- Each streak is a tuple `(start, end, length)`: `start` and `end` are `datetime.date` objects
  (both **inclusive**) and `length == (end - start).days + 1`.
- Streaks of a customer are in chronological order. The dict is ordered by `customer_id`
  ascending. Customers without a qualifying streak are **not** in the dict.
- `records` can be any iterable, in any order, and is read **once**. No records give `{}`.

## Example

`min_days = 5` (UTC dates, status COMPLETED unless noted):

| customer | purchase dates | result |
|---|---|---|
| 501 | Mar 1, Mar 2, Mar 2, Mar 3, Mar 4, Mar 5 | `[(Mar 1, Mar 5, 5)]` |
| 502 | Mar 1, 2, 3, 4, 6, 7 | not reported (longest run 4) |
| 503 | Dec 30, Dec 31, Jan 1, Jan 2, Jan 3 | `[(Dec 30, Jan 3, 5)]` |
| 504 | Mar 1..5 and Mar 20..26 | `[(Mar 1, Mar 5, 5), (Mar 20, Mar 26, 7)]` |

## Corner cases to think about

- Exactly 4 days (no) vs exactly 5 (yes); `min_days` other than 5.
- Many purchases on one day.
- Runs across a month end, a year end and leap day 2024-02-29 (and not across 2025-02-29, which
  does not exist).
- A day whose only record is cancelled or pending breaks the run.
- A purchase at 23:30 in UTC-5 belongs to the **next** UTC date.
- Two disjoint qualifying runs; a run longer than `min_days`.
- Guests, empty input, unordered input.

## Expected complexity

At most **O(n log n)** time for n records, and ideally O(n). The tests use 200,000 records over
5,000 customers. Memory should be proportional to the number of distinct (customer, day) pairs,
not to the number of days in the calendar.

## Clarify before you code

- Which timezone defines "the same day"? (UTC.) Which statuses count? (`COMPLETED` only.)
- Should a 6-day run be reported once or as overlapping 5-day windows? (Once, maximal.)
- Do guests count? (No.)
