# PY-018 · Design a small LRU cache

**Topic:** algorithms & interview patterns · **Level:** medium · **Interview time:** ~25 min · **Module:** `python/practice/02_algorithms/PY-018.py`

## Scenario

A pricing service looks up product details for every scanned item. The lookup is slow, so the
service keeps the most recently used products in memory, with a hard limit on how many. When
the cache is full and a new product arrives, the product that was **used least recently** is
thrown out. The cache sits on the hot path of every scan, so each operation must be fast
regardless of capacity (tens of thousands of entries).

## Class contract

```text
class LRUCache:
    def __init__(self, capacity: int, on_evict: Callable[[Any, Any], None] | None = None) -> None
    def get(self, key, default=None)
    def put(self, key, value) -> None
    def __len__(self) -> int
    def __contains__(self, key) -> bool
```

- **Capacity:** `capacity` must be an `int` that is at least 1. A `bool`, `float` or other type
  raises `TypeError`. A value below 1 raises `ValueError`.
- **Keys** are any hashable values. **Values** can be anything, including `None`.
- **`get(key, default=None)`** returns the stored value and marks the key as the **most recently
  used**. If the key is missing it returns `default` and changes nothing (it never inserts).
  A stored value of `None` is a real hit: it is returned and the key becomes most recently used.
- **`put(key, value)`**:
  - new key: store it as the most recently used. If the cache now holds more than `capacity`
    entries, evict the **least** recently used one;
  - existing key: replace the value and mark the key most recently used. This never evicts
    anything and never calls `on_evict`.
- **`__len__`** is the number of entries currently stored (never more than `capacity`).
- **`__contains__`** (`key in cache`) reports whether the key is stored. It does **not** change the
  recency order: checking for a key must not protect it from eviction.
- **`on_evict(key, value)`** (optional) is called once for each entry removed to make room, with the
  evicted key and its value, after the entry has been removed. It is not called for replaced values.
- **Complexity:** `get`, `put` and `__contains__` run in **O(1)** average time. The tests do
  200,000 operations on a 50,000-entry cache.

## Example

```text
c = LRUCache(2)
c.put("A", 1); c.put("B", 2)       # order, oldest to newest: A, B
c.get("A")                          # -> 1; order: B, A
c.put("C", 3)                       # full: evicts B; order: A, C
"B" in c                            # -> False
"A" in c                            # -> True   (does not refresh A)
c.put("D", 4)                       # evicts A (still the oldest, since `in` did not refresh it)
```

## Corner cases to think about

- Capacity 1.
- Updating an existing key when the cache is full (nothing is evicted).
- Reading a key makes it the newest; checking `in` does not.
- Missing key with and without a `default`; a stored `None` value.
- Eviction callback: called for the right entry, not for updates.

## Expected complexity

O(1) average per operation, O(capacity) memory. Do not search a list on each access.

## Clarify before you code

- Does a read count as "use"? (Yes for `get` and `put`; no for `in`.)
- What happens on a put of an existing key at full capacity? (Update only, no eviction.)
- Thread safety? (Not required here. Mention how you would add it.)
