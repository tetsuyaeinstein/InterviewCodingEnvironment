# PY-013 · Merge kiosk outage windows

**Topic:** algorithms & interview patterns · **Level:** medium · **Interview time:** ~20 min · **Module:** `python/practice/02_algorithms/PY-013.py`

## Scenario

Several monitoring systems report when a kiosk was **unavailable**: the network probe, the
payment terminal and the app heartbeat. Each report is a window `[start, end)`. The windows arrive
unsorted, overlap, and often repeat each other. The SLA report needs the **distinct outage
periods**: the union of all windows, as a sorted list of non-overlapping windows.

## Function contract

```text
merge_intervals(intervals: Iterable[tuple[T, T]]) -> list[tuple[T, T]]
```

`T` is any totally ordered type that is used consistently: `int` (epoch seconds), or
timezone-aware `datetime`.

- Each window is **half-open**: `[start, end)` contains `start` and excludes `end`.
- **Touching windows merge.** `[1, 5)` and `[5, 9)` cover every instant from 1 up to 9 without a
  gap, so they become `[1, 9)`.
- Windows with a **positive gap** between them stay separate: `[1, 5)` and `[6, 9)`.
- A **zero-length** window (`start == end`) covers no instant. It is **dropped**: it never
  appears in the output and never joins two other windows.
- A window with `start > end` is invalid. Raise `ValueError`.
- Return a new list of `(start, end)` **tuples**, sorted by `start`. Consecutive output windows are
  separated by a positive gap (`previous_end < next_start`).
- The input can be any iterable (list, generator) and arrives in any order. Do not mutate it.
- An empty input returns `[]`.

## Examples

| input | output |
|---|---|
| `[(1, 3), (2, 6), (8, 10), (15, 18)]` | `[(1, 6), (8, 10), (15, 18)]` |
| `[(5, 9), (1, 5)]` | `[(1, 9)]` (touching, unsorted) |
| `[(1, 10), (2, 3), (4, 5)]` | `[(1, 10)]` (nested) |
| `[(1, 4), (6, 6), (6, 9)]` | `[(1, 4), (6, 9)]` (zero-length dropped) |
| `[(4, 4)]` | `[]` |
| `[(3, 1)]` | `ValueError` |

## Corner cases to think about

- A window fully inside another, and a long window that swallows several later ones.
- Touching vs gap of one unit.
- Zero-length windows on their own, inside another window, or exactly where two windows touch.
- Duplicate windows.
- Datetime windows, including a window that ends exactly at midnight.

## Expected complexity

O(n log n) time for n windows, O(n) memory for the result. Be ready to say what dominates.

## Clarify before you code

- Are the ends inclusive or exclusive? (Exclusive here. With inclusive integer ends, `[1, 4]` and
  `[5, 9]` would merge too, which is a different rule.)
- What does a zero-length window mean: a sensor glitch, or an instantaneous event to keep?
- Should invalid windows be skipped or rejected? (Rejected here.)
