# PY-016 · First transaction at or after a cutoff

**Topic:** algorithms & interview patterns · **Level:** easy · **Interview time:** ~10 min · **Module:** `python/practice/02_algorithms/PY-016.py`

## In plain words

> "A big sorted list of transaction times is read-only and slow to access. What is the position of the first transaction at or after 14:00?"

**You return:** `first_at_or_after(seq, target)` returns the smallest index `i` with `seq[i] >= target`.

**The fine print, in short:**
- If every element is smaller, or `seq` is empty, return `len(seq)`. With duplicates of `target`, return the first one's index.
- Only use `len(seq)` and `seq[index]`. Don't copy, slice or iterate it.
- Each read is expensive, so you may only read a small handful of elements, not scan from the start.

## Scenario

A kiosk's transaction timestamps are stored **sorted ascending** in a large, indexed, read-only
sequence. Support asks "what was the first transaction at or after 14:00?" many times per second,
so scanning from the start is not acceptable. You need the **position** of that transaction.

## Function contract

```text
first_at_or_after(seq: Sequence[T], target: T) -> int
```

- `seq` is sorted in non-decreasing order and may contain **duplicates**. `T` is any type whose
  values can be compared with `<`: `int`, `str`, timezone-aware `datetime`, ...
- Return the **smallest index `i`** such that `seq[i] >= target`.
- If every element is smaller than `target` (or `seq` is empty), return `len(seq)`.
- With duplicates equal to `target`, return the index of the **first** one.
- `seq` is accessed only through `len(seq)` and `seq[index]`. It may be a lazily-loaded
  sequence where each access is expensive, so the tests count `__getitem__` calls. Do not copy it,
  slice it, or iterate over it.
- Do not mutate `seq`.

## Examples

| seq | target | result |
|---|---|---|
| `[10, 20, 20, 20, 30]` | `20` | `1` |
| `[10, 20, 20, 20, 30]` | `25` | `4` |
| `[10, 20, 20, 20, 30]` | `5` | `0` |
| `[10, 20, 20, 20, 30]` | `31` | `5` (= `len(seq)`) |
| `[]` | `7` | `0` |

## Corner cases to think about

- Target smaller than everything, larger than everything, or between two values.
- A long run of duplicates equal to the target.
- Empty and single-element sequences.
- Datetimes, with duplicates at the boundary.

## Expected complexity

**O(log n)** element reads. The tests allow about `2 * log2(n) + 5` reads on a sequence of one
million elements and fail a linear scan.

## Clarify before you code

- First element **at or after** the cutoff (`>=`), not strictly after (`>`). A cutoff equal to a
  timestamp includes it.
- What does "not found" return? (`len(seq)`, never `-1` or an exception.)
