# PY-014 · Most frequently scanned SKUs

**Topic:** algorithms & interview patterns · **Level:** medium · **Interview time:** ~20 min · **Module:** `python/practice/02_algorithms/PY-014.py`

## In plain words

> "Over millions of scans today, which K SKUs were scanned most often? The trending-now screen must show the same list on every server."

**You return:** `top_k_frequent(skus, k)` returns up to `k` `(sku, count)` tuples, most frequent first.

**The fine print, in short:**
- Ties go to the SKU that sorts first in plain string order. `None` SKUs are ignored; SKUs are compared exactly.
- `k == 0` gives `[]`; a negative `k` raises `ValueError`; a non-int or bool `k` raises `TypeError`. Check `k` before reading the stream.
- The stream can be read only once, and there are many events but far fewer distinct SKUs.

## Scenario

Every basket line scanned at a kiosk produces one SKU event. Merchandising wants the **K most
frequently scanned SKUs** of the day for the "trending now" screen. A day has millions of scan
events but only tens of thousands of distinct SKUs, and K is small (5 to 50). The screen is
rendered by several servers from the same data, so the list must be **identical** on every server:
ties need a fixed rule.

## Function contract

```text
top_k_frequent(skus: Iterable[str | None], k: int) -> list[tuple[str, int]]
```

- `skus` is a stream of SKU codes (strings), one per scan, in any order. It may be a generator,
  so it can only be read **once**.
- `None` means "SKU missing from the event". Ignore it: it is never counted or returned.
- SKUs are compared exactly (case-sensitive, no trimming).
- Return up to `k` tuples `(sku, count)` ranked by:
  1. `count` **descending**;
  2. `sku` **ascending** (plain string order) on ties.
- If `k` is larger than the number of distinct SKUs, return all of them, ranked.
- `k == 0` returns `[]`.
- `k` must be an `int`. A `bool`, `float` or anything else raises `TypeError`. A negative `k`
  raises `ValueError`. Validate `k` **before** reading the stream.

## Example

`skus = ["B-7", "C-3", "A-1", "B-7", "A-1", None, "D-9", "C-3", "B-7"]`

| k | result |
|---|---|
| 1 | `[("B-7", 3)]` |
| 2 | `[("B-7", 3), ("A-1", 2)]` |
| 3 | `[("B-7", 3), ("A-1", 2), ("C-3", 2)]` |
| 10 | `[("B-7", 3), ("A-1", 2), ("C-3", 2), ("D-9", 1)]` |
| 0 | `[]` |

`"A-1"` and `"C-3"` are tied on 2. `"A-1"` ranks first because it sorts first, even though
`"C-3"` was scanned earlier. The first-seen order plays no part in the ranking.

## Corner cases to think about

- The K-th and (K+1)-th SKUs are tied.
- All SKUs have the same count.
- Empty stream, a stream of only `None`.
- `k` larger than the distinct count; `k == 0`; invalid `k` with an empty stream.
- Case-sensitive codes: `"sku-1"` and `"SKU-1"` are different SKUs.

## Expected complexity

Counting is O(n) for n events. Ranking should cost **O(d log k)** (or O(d) with extra memory) for
d distinct SKUs, not O(n log n). The tests use 1,000,000 events over 100,000 SKUs. Be ready to
compare the ranking options.

## Clarify before you code

- What breaks ties: first seen, most recent, or SKU code? (SKU code ascending here.)
- Exactly K rows, or everyone tied with the K-th? (Exactly K here.)
- Are missing SKUs an error or noise? (Noise: skipped.)
