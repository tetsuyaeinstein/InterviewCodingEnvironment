# PY-019 · Peak queue length in every K-minute window

**Topic:** algorithms & interview patterns · **Level:** hard · **Interview time:** ~30 min · **Module:** `python/practice/02_algorithms/PY-019.py`

## Scenario

A kiosk reports its queue length once per minute. Capacity planning wants, for every
K-minute stretch, the **peak queue length** inside it, to build a "worst K minutes" chart and to
alert when a peak stays above a threshold. A day has 1,440 readings per kiosk, but the batch job
re-computes a year of history for thousands of kiosks, with K up to 1,000, so the cost per window
must not grow with K.

## Function contract

```text
sliding_window_max(values: Sequence[int], k: int) -> list[int]
```

- A **window** is `k` consecutive readings: `values[i : i + k]`. Windows are produced for every
  start `i` from `0` to `len(values) - k`, in that order.
- Return a list with the **maximum of each window**: `len(values) - k + 1` numbers.
- `values` can contain duplicates, zeros and **negative** numbers (for example a queue that is
  "ahead of target" by -3).
- `k` must be an `int`. A `bool`, `float` or anything else raises `TypeError`. `k < 1` raises
  `ValueError`. Validate `k` first, even when `values` is empty.
- If `k > len(values)` there is no complete window: return `[]`. The same goes for an empty
  `values`.
- Do not mutate `values`. Return a new list.

## Examples

| values | k | result |
|---|---|---|
| `[1, 3, -1, -3, 5, 3, 6, 7]` | `3` | `[3, 3, 5, 5, 6, 7]` |
| `[4, 2, 12, 3]` | `1` | `[4, 2, 12, 3]` |
| `[4, 2, 12, 3]` | `4` | `[12]` |
| `[4, 2, 12, 3]` | `5` | `[]` |
| `[-5, -2, -9]` | `2` | `[-2, -2]` |
| `[7, 7, 7]` | `2` | `[7, 7]` |
| `[]` | `3` | `[]` |
| `[1, 2]` | `0` | `ValueError` |

## Corner cases to think about

- Duplicates of the maximum: when the max leaves the window, an equal value may still be inside.
- Strictly increasing and strictly decreasing inputs (the two extremes for most approaches).
- All values negative.
- `k == 1` and `k == len(values)`.
- `k` larger than the data, and invalid `k` with empty data.

## Expected complexity

**O(n)** time (amortised) for n readings, independent of `k`, and O(k) extra memory.
O(n log n) is acceptable but be ready to say what you give up. The tests use `n = 300,000` and
`k = 2,000`, so the obvious "`max(values[i:i+k])` for every window" (O(n · k), about 600 million
steps) will not finish in time.

## Clarify before you code

- What should happen when `k` exceeds the data, or `k` is 0? (`[]` and `ValueError`.)
- Is the input a list or a stream? (A list here. Think about how it changes for a stream.)
- Are there ties for the maximum? (They don't change the answer, only your bookkeeping.)
