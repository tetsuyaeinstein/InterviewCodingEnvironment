# PY-011 · Match a refund to a pair of charges

**Topic:** algorithms & interview patterns · **Level:** medium · **Interview time:** ~20 min · **Module:** `python/practice/02_algorithms/PY-011.py`

## In plain words

> "A provider sent one refund that covers two earlier charges on the same card. Find the two charges, given in cents, that add up exactly to the refund."

**You return:** `find_refund_pair(amounts_cents, target_cents)` returns a tuple of positions `(i, j)` with `i < j`, or `None` if no pair adds up to `target_cents`.

**The fine print, in short:**
- You can't use one position twice, but two positions with the same amount are fine. Amounts can be zero or negative.
- If several pairs work, pick the one whose second position `j` is smallest, then the smallest `i`.
- A non-int `target_cents` (including bool) raises `TypeError`. A card can have hundreds of thousands of charges, so trying every pair is too slow.

## Scenario

A payment provider sometimes sends a **single refund** that covers **two earlier charges** on the
same card. The reconciliation job has the card's charges for the day, in arrival order, as integer
**cents**. It must find two charges whose amounts add up exactly to the refund. Auditors re-run the
job and compare outputs, so when several pairs match, the job must always pick **the same pair**.

A busy merchant card can have hundreds of thousands of charges per day.

## Function contract

```text
find_refund_pair(amounts_cents: Sequence[int], target_cents: int) -> tuple[int, int] | None
```

- Return a tuple of positions `(i, j)` with `i < j` and
  `amounts_cents[i] + amounts_cents[j] == target_cents`.
- An index can't be used twice. Two **different** positions holding the same amount are fine.
- **Answer policy when several pairs match.** Choose the pair whose **second** position `j` is
  smallest: the refund is matched as early in the stream as possible. If several pairs share that
  `j`, choose the smallest `i`.
- Return `None` when no pair matches, including for empty or one-element input.
- Amounts can be zero or negative (reversals and adjustments).
- `target_cents` must be an `int`. A `bool`, `float`, `Decimal` or anything else raises
  `TypeError`. You may assume the amounts themselves are ints.
- Do not mutate the input.

## Examples

| amounts_cents | target_cents | result | why |
|---|---|---|---|
| `[1250, 400, 850, 2100]` | `1250` | `(1, 2)` | 400 + 850 |
| `[500, 300, 500]` | `1000` | `(0, 2)` | same amount, different positions |
| `[500, 300]` | `1000` | `None` | 500 can't be used twice |
| `[300, 700, 600, 400]` | `1000` | `(0, 1)` | (0, 1) completes at j = 1, before (2, 3) at j = 3 |
| `[200, 200, 800]` | `1000` | `(0, 2)` | j = 2 for both (0, 2) and (1, 2); smaller i wins |
| `[-150, 900, 750]` | `600` | `(0, 2)` | -150 + 750; negative amounts are ordinary values |
| `[]` | `0` | `None` | |

## Corner cases to think about

- The same amount twice, and an amount that is exactly half the target.
- Many duplicates of one amount: which index do you remember for it?
- Several valid pairs: does your approach find the one the policy asks for?
- Empty input, one element, zero and negative amounts.

## Expected complexity

Time **O(n)** expected, or O(n log n). The tests use 200,000 charges with the only match near the
end, so the O(n²) "try every pair" approach will not finish in time.

## Clarify before you code

- What if several pairs match? (The policy above; the strongest candidates ask before coding.)
- Can one charge pay for itself twice? (No: two distinct positions.)
- Why cents and not floats? (`0.1 + 0.2 != 0.3` in binary floating point.)
