# PY-037 · Canonical fingerprint with schema evolution: explanation

## Approach (`PY-037.py`)

1. Select the named fields; drop those whose value is `None` or absent.
2. Turn each value into `[type_tag, text]`: `num` (normalised decimal), `str`, `bool`, `bytes` (hex),
   `ts` (UTC, fixed format with microseconds), `date`.
3. Build `[[field, tag, text], ...]` sorted by field name.
4. `json.dumps(..., separators=(",", ":"))` -> UTF-8 -> SHA-256 hex.

JSON string escaping makes the encoding **injective** (distinct canonical forms never serialise to
the same bytes), and sorting by field name removes order dependence.

| input difference | fingerprint |
|---|---|
| key order, `fields` order | same |
| `1`, `Decimal("1.00")`, `Decimal("1E0")` | same |
| `None` vs missing key | same |
| `None` vs `""` vs `"None"` | all different (the last two are real strings) |
| `("ab","c")` vs `("a","bc")` on two fields | different (field names + escaping delimit) |
| `{"a": "b"}` vs `{"b": "a"}` | different |
| `True` vs `1` vs `"1"` | different |
| `12:00Z` vs `21:00+09:00` | same instant -> same |
| `date` vs midnight `datetime` vs ISO string | different |

## Why schema evolution works

If NULL is *encoded* (`"tier": null`), adding a column changes the byte string of every row.
If NULL is *omitted*, a row that does not use the new column is byte-for-byte what it was. The
price: you can no longer distinguish "field absent" from "field NULL", which for change detection
is what you want, and that is a documented policy. If you do need the distinction, the alternative is an
explicit **policy version** that is hashed in (`v1|...`) and a migration that rewrites stored fingerprints,
which is exactly the 2 a.m. job you wanted to avoid.

## Why the edge cases matter

- **Delimiter joins** are not injective. Always escape or length-prefix.
- **`str(Decimal)` is representation-dependent:** two systems that format `1.10` and `1.1` differently
  would flag every row as changed. Normalise numeric *values*, not representations.
- **Offsets:** `isoformat()` of the same instant differs by offset; convert to UTC first. Reject naive
  datetimes: guessing a zone is a silent data error.
- **Types:** `True == 1` in Python, and `hash(1) == hash(1.0)`; tagging keeps them apart where it matters.
- **`Decimal.normalize()` is lossy** for numbers wider than the context precision (28 digits by default): `10**30` and `10**30 + 1` would get the same fingerprint. Strip trailing zeros via `as_tuple()` instead.
- **Floats** are refused: `0.1 + 0.2 != 0.3` and `repr` is not stable across systems. Convert to `Decimal` deliberately upstream.

## Production notes

- Truncating the digest (e.g. 128 bits) is fine for change detection; collision probability for n rows is about
  n²/2^129. Use a full 256 bits for dedup keys in audits.
- Fingerprints belong in the target table (`row_hash`) so the merge condition is `src.hash <> tgt.hash`
  (the SCD2 pattern, PY-036) and incremental loads compare one column.
- Hash in the warehouse and in Python **with the same canonicalisation**, or comparisons across systems
  (PY-028 reconciliation) fail. Write the policy down and test it with golden digests.
- Spark: `sha2(concat_ws('\u0001', ...), 256)` has the delimiter problem; prefer `to_json(struct(...))` with sorted fields.
