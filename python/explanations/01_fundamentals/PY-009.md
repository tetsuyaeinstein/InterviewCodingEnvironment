# PY-009 · Event-type frequency report: explanation

## Approach (`PY-009.py`)

1. **Normalise:** `" ".join(s.split()).lower()`. `str.split()` with no argument splits on any
   run of Unicode whitespace (tabs, newlines, non-breaking spaces) and drops leading/trailing
   empties. So one expression trims, collapses and handles blank strings (they become `""`, which
   we ignore).
2. **Count** with `collections.Counter`, a dict subclass built for this.
3. **Order:** `sorted(items, key=lambda kv: (-kv[1], kv[0]))`. That is count descending, then name
   ascending: a total order, so the report is identical on every run.

| raw | after `split()` + join | after `lower()` |
|---|---|---|
| `" coin_deposit "` | `coin_deposit` | `coin_deposit` |
| `"bill  jam"` | `bill jam` | `bill jam` |
| `"BILL\tJAM"` | `BILL JAM` | `bill jam` |
| `"  "` | `""` | ignored |

Time O(n + u log u), space O(u).

## Common wrong answers

- **`Counter.most_common()`** as the final answer: ties come out in **first-seen** order. That
  is deterministic for one input, but differs between days, kiosks and shard orders, so the
  diffed report flaps.
- **`sorted(..., key=lambda kv: kv[1], reverse=True)`:** same tie problem.
- **`sorted(..., key=lambda kv: (kv[1], kv[0]), reverse=True)`:** ties come out in reverse
  alphabetical order.
- **`s.strip().lower()` only:** `"bill  jam"` and `"bill jam"` become two rows.
- **`s.replace(" ", "")`:** merges `"bill jam"` with `"billjam"`. Over-normalisation is as
  wrong as under-normalisation; follow the contract.
- **Silently skipping non-strings:** an `int` event type means an upstream schema change.
  Failing loudly is the contract here.

## Alternatives and runtime notes

- `str.casefold()` is the Unicode-correct choice for case-insensitive matching (`"Straße"` →
  `"strasse"`), but it changes how names are *displayed*. If you use it, keep a display name
  separately. The contract fixes `lower()`.
- `re.sub(r"\s+", " ", s).strip()` is equivalent to `" ".join(s.split())`, slower, and easier to
  get subtly wrong.
- When you only need the top N of a huge vocabulary, `heapq.nsmallest(n, items, key=(-count, name))`
  avoids the full sort (see PY-003).

## Scale-up discussion

- **Billions of events:** counting is a mergeable aggregation. Count per partition/shard, then
  sum the counters (`Counter.update` / `+`). That is exactly what `GROUP BY` or Spark's
  `reduceByKey` does. Normalise **before** the shuffle, or the shuffle carries every spelling
  variant.
- **Unbounded vocabularies** (free-text event types after a firmware bug): exact counting needs
  memory proportional to distinct names. Count-Min Sketch or Space-Saving give bounded-memory
  approximate heavy hitters.
- **Canonical names belong upstream:** maintain a mapping table (`raw spelling → canonical
  event`) with ownership, and alert on new spellings instead of normalising forever downstream.
