# SQL-016 · First and latest purchase, and time to first purchase

**Topic:** aggregates & windows · **Level:** medium · **Interview time:** ~15 min · **Mode:** query

## Business context

The growth team measures **activation**: how many days pass between a customer registering and
their first real purchase. They also want each customer's first and latest purchase date and
the number of purchases, for **every** registered customer. Customers who never bought anything
are the most interesting segment, so they must be in the output too.

## Source tables

| table | grain | columns you need |
|---|---|---|
| `customers` | one row per customer | `customer_id`, `registered_at` (timestamptz, UTC) |
| `transactions` | one row per checkout transaction | `customer_id`, `transaction_ts` (timestamptz, UTC), `transaction_status` |

## Requirements

1. A purchase is a `COMPLETED` transaction. Whole history, no date filter.
2. All dates are **UTC calendar dates**: `registration_date` is the UTC date of `registered_at`,
   purchase dates are UTC dates of `transaction_ts`.
3. `first_purchase_date` / `last_purchase_date`: UTC dates of the customer's earliest and latest
   completed transaction.
4. `completed_purchases`: number of completed transactions (`0` if none).
5. `days_to_first_purchase` = `first_purchase_date − registration_date` in **whole calendar
   days** (a first purchase on the registration date gives 0). It is not "elapsed 24-hour
   periods": registering at 23:00 and buying at 01:00 the next day is 1 day.
6. One row per customer in `customers`. Customers without a completed purchase are returned
   with NULL `first_purchase_date`, `last_purchase_date` and `days_to_first_purchase`, and
   `completed_purchases = 0`.

## Output contract

| column | type | notes |
|---|---|---|
| `customer_id` | integer | every customer exactly once |
| `registration_date` | date | |
| `first_purchase_date` | date | NULL if never purchased |
| `last_purchase_date` | date | NULL if never purchased |
| `completed_purchases` | integer | 0 if never purchased |
| `days_to_first_purchase` | integer | NULL if never purchased |

Ordering: none required.

## Illustrative example (not the real data)

| customer | registered_at (UTC) | transactions (UTC, status) | first / last | count | days |
|---|---|---|---|---|---|
| 601 | 2024-05-10 22:30 | 2024-05-11 01:00 COMPLETED | 05-11 / 05-11 | 1 | 1 |
| 602 | 2024-05-10 08:00 | 05-12 PENDING; 05-20 COMPLETED; 06-02 COMPLETED | 05-20 / 06-02 | 2 | 10 |
| 603 | 2024-05-11 09:00 | 05-12 CANCELLED | NULL / NULL | 0 | NULL |

## Edge cases you must handle

- A non-completed transaction **before** the first completed one.
- A non-completed transaction **after** the latest completed one.
- Customers with no transactions, or only non-completed ones.
- Registration late in the day and a first purchase early the next day.
- Leap years between registration and first purchase.

## Constraints

- One read-only `SELECT` / `WITH` statement, valid PostgreSQL 17.
- About 2,000 customers in the small seed. Expect a question on 20M customers / 500M transactions.

## Clarify before you code (what a strong candidate asks)

- Do pending or cancelled transactions count as a first purchase?
- Calendar days or elapsed time? Which time zone defines the day?
- Should customers with no purchases appear, and with NULL or 0 values?
- What if a purchase is recorded before the registration timestamp (bad data)?
