# SQL-012 · Second-largest distinct transaction amount per store

**Topic:** aggregates & windows · **Level:** medium · **Interview time:** ~15 min · **Mode:** query

## In plain words

> "For each store in 2025, what is the biggest completed transaction amount, and what is the next biggest different amount?"

**You return:** one row per store: `store_id`, `highest_amount`, `second_highest_amount` (NULL if there is none).

**The fine print, in short:**
- Only **completed** 2025 (UTC) transactions, guests included.
- The second amount must be strictly smaller than the highest. Repeated amounts count as one value.
- A store with only one distinct amount is still returned, with NULL as the second.

## Business context

Fraud operations flags a store when one basket is far larger than everything else. Their rule
compares each store's **largest** completed transaction amount of 2025 with the **next-largest
different amount**. They have been burned before by reports where "second largest" was just a
copy of the largest (two baskets of the same value), so they insist on **distinct amounts**.

## Source table

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction | `store_id`, `transaction_ts` (timestamptz, UTC), `gross_amount`, `transaction_status` |

## Requirements

1. Scope: `COMPLETED` transactions with a UTC business date in 2025, i.e. `transaction_ts` in
   `[2025-01-01 00:00:00 UTC, 2026-01-01 00:00:00 UTC)`. Guest checkouts count (this is about
   baskets, not customers).
2. `highest_amount`: the largest `gross_amount` in scope for the store.
3. `second_highest_amount`: the largest `gross_amount` that is **strictly smaller** than
   `highest_amount`. Several transactions with the same amount count as **one** value.
4. If a store has fewer than two distinct amounts in scope, `second_highest_amount` is **NULL**
   (the store is still returned).
5. One row per store that has at least one completed transaction in scope. Stores without any
   are not returned.

## Output contract

| column | type | notes |
|---|---|---|
| `store_id` | integer | one row per store |
| `highest_amount` | numeric | 2 decimals |
| `second_highest_amount` | numeric | 2 decimals, NULL if there is no second distinct value |

Ordering: none required.

## Illustrative example (not the real data)

| store | completed amounts in scope | highest | second highest |
|---|---|---|---|
| 901 | 40, 40, 35, 20 | 40.00 | 35.00 |
| 902 | 12, 12, 12 | 12.00 | NULL |
| 903 | 99 (CANCELLED), 50, 45 | 50.00 | 45.00 |

## Edge cases you must handle

- Two or more transactions sharing the highest amount (and the second-highest amount).
- A store with a single distinct amount (many transactions, all the same value).
- A large non-completed transaction.
- Transactions just outside the year.

## Constraints

- One read-only `SELECT` / `WITH` statement, valid PostgreSQL 17.
- Expect a follow-up: "now the N-th largest distinct amount".

## Clarify before you code (what a strong candidate asks)

- "Second largest" by distinct value, or the second row when sorted?
- What should a store with only one distinct amount show: NULL, the same value, or no row?
- Which statuses count? Do refunds reduce the amount? (Not in this exercise.)
- UTC year or store-local year?
