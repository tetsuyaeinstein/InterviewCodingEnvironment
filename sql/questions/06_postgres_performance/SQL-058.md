# SQL-058 · Calendar of sale-less days for a store (generate_series anti-join)

**Topic:** PostgreSQL performance & calendars · **Level:** easy · **Interview time:** ~15 min · **Mode:** query

## Business context

Store 4 (a small Phoenix kiosk) is under review. Operations want to know **on which days of Q1
2025 the store made no sale at all**, so they can compare against opening hours and staffing. The
transactions table only has rows for days that had activity, so "days with no rows" cannot be
found by querying it alone: you need a complete calendar to compare against.

## Source table

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction | `store_id`, `transaction_ts` (timestamptz, UTC), `transaction_status` |

## Requirements

1. Store **4** only.
2. Calendar: every UTC date from **2025-01-01 through 2025-03-31, both inclusive** (90 days).
3. A date has a sale when the store has at least one `COMPLETED` transaction whose UTC calendar date
   is that date. Pending, cancelled and declined transactions are **not** sales.
4. Return every date in the calendar that has **no** sale.
5. Also return the ISO weekday number (Monday = 1 ... Sunday = 7) of each date.

## Output contract

| column | type | notes |
|---|---|---|
| `sale_date` | date | the sale-less date |
| `iso_weekday` | integer | 1 = Monday ... 7 = Sunday |

Ordering: none required.

## Illustrative example (not the real data)

If a store had completed sales only on Jan 2 and Jan 4, then for the calendar Jan 1 ... Jan 5 the
answer is Jan 1 (Wed = 3), Jan 3 (Fri = 5), Jan 5 (Sun = 7), assuming those weekdays.

## Edge cases you must handle

- The first and last day of the calendar can be sale-less and must be reported.
- A day whose only transactions were pending, cancelled or declined is sale-less.
- A day with a completed sale **and** a cancelled one is not sale-less.
- Several transactions on one day must not create duplicate rows.
- The calendar must contain 90 distinct days (no off-by-one at either end).

## Constraints

One read-only `SELECT`/`WITH`, PostgreSQL 17. Do not hard-code the list of sale-less dates.

## Clarify before you code (what a strong candidate asks)

- UTC date or store-local date? (Store 4 is in Phoenix, UTC-7 with no DST; here: UTC.)
- Do refunds or zero-value sales count?
- Should dates before the store's opening or after its closing be excluded?
- Is a persistent calendar (date dimension) table available in the warehouse?
