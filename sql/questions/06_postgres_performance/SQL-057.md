# SQL-057 · Expand JSON item arrays into rows safely (arrays, objects, nulls, bad quantities)

**Topic:** PostgreSQL performance & semi-structured data · **Level:** medium · **Interview time:** ~25 min · **Mode:** query

## Business context

Merchandising wants "units per SKU per checkout" from the clickstream. The basket lives in
`customer_events.payload -> 'items'`, which is supposed to be an array of `{sku, qty}` objects
but, in the wild, is also an empty array, JSON `null`, missing, or a single bare object. One
malformed event must not break the nightly job that unnests hundreds of millions of events.

## Source table

| table | grain | columns you need |
|---|---|---|
| `customer_events` | one row per client event | `event_id` (bigint), `event_ts` (timestamptz, UTC), `event_type`, `payload` (jsonb) |

Item shape: `{"sku": "SKU-00001", "qty": 2}`. `qty` is usually a JSON number but can be a string.

## Requirements

1. Scope: events with `event_type = 'checkout'` and `event_ts` on **2025-08-15 UTC**
   (`[2025-08-15 00:00, 2025-08-16 00:00)`).
2. Output **one row per (event, sku)** with `total_qty`: the **sum** of the quantities of all
   lines of that sku in the event. A sku that appears twice in one basket is one row.
3. `items` handling:
   - JSON array: each element is a line.
   - JSON **object**: treated as a **single line** (some producers send one item un-wrapped).
   - JSON `null`, missing, an empty array, or any other type: the event produces no rows.
4. A line is **dropped** when its `sku` is missing or JSON `null`, or when its `qty` is not a
   whole number (a string such as `"two"`, a decimal, JSON `null` or missing). Strings holding
   a whole number (`"3"`) are valid.
5. Events that produce no lines simply do not appear.

## Output contract

| column | type | notes |
|---|---|---|
| `event_id` | bigint | |
| `sku` | text | |
| `total_qty` | bigint | sum of `qty` over the event's lines of that sku |

Ordering: none required.

## Illustrative example (not the real data)

| payload items | rows produced |
|---|---|
| `[{"sku":"A","qty":1},{"sku":"A","qty":2},{"sku":"B","qty":"4"}]` | `(A, 3)`, `(B, 4)` |
| `{"sku":"C","qty":1}` (bare object) | `(C, 1)` |
| `[{"sku":null,"qty":5},{"sku":"D","qty":"many"}]` | none |
| `[]`, `null`, key missing | none |

## Edge cases you must handle

- `jsonb_array_elements` and friends **raise an error** when given a non-array: the query must
  survive an object, a JSON null and a missing key in the same scan.
- The same sku twice in one array: one output row with the summed quantity.
- A line with a JSON-null sku, or a non-numeric quantity: excluded, not an error and not 0.
- The basket of an event that has an invalid line but another valid line keeps the valid one.

## Constraints

One read-only `SELECT`/`WITH`, PostgreSQL 17. Do not assume `items` is always an array.

## Clarify before you code (what a strong candidate asks)

- Should an invalid line be dropped, counted as 0, or should the event be rejected?
- Is a bare object a data error or a legitimate single-item basket?
- Do events with no usable lines need a row (for example `sku` NULL) to be countable downstream?
- Is `sku` case-sensitive and trimmed already?
