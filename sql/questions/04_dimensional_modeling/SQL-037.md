# SQL-037 · Products frequently bought together

**Topic:** dimensional modeling · **Level:** medium · **Interview time:** ~20 min · **Mode:** query

## Business context

Merchandising wants a "bought together" list for the holiday season: which pairs of products end
up in the same basket most often. The result will feed a recommendation table, so every pair must
appear **once** and the counts must be about **baskets**, not order lines.

## Source tables

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction (a basket) | `transaction_id`, `transaction_ts` (timestamptz, UTC), `transaction_status` |
| `transaction_items` | one row per order line | `transaction_id`, `line_number`, `product_id` |

A product can appear on **two different lines** of the same transaction.

## Requirements

1. Scope: `COMPLETED` transactions with `transaction_ts` in **[2025-11-01, 2026-01-01) UTC**
   (guest checkouts included).
2. A pair is two **different** products that both occur in the same transaction. Report each pair
   once, as `product_a < product_b`. A product is never paired with itself.
3. `co_occurrences` = number of **distinct transactions** that contain both products. A product
   on two lines of one transaction counts that transaction once.
4. Return only pairs with `co_occurrences >= 2`.

## Output contract

| column | type | notes |
|---|---|---|
| `product_a` | integer | smaller product id |
| `product_b` | integer | larger product id |
| `co_occurrences` | integer | distinct baskets containing both |

Ordering: none required.

## Illustrative example (not the real data)

| transaction | lines (product ids) |
|---|---|
| T1 | 901, 902 |
| T2 | 902, 901, 901 |
| T3 | 901, 903 |
| T4 | 904, 904 |

| product_a | product_b | co_occurrences |
|---|---|---|
| 901 | 902 | 2 |

(901/903 occurs once, below the threshold. T4 has only one distinct product: no pair.)

## Edge cases you must handle

- A product repeated on several lines of one basket.
- Baskets with a single distinct product (no pairs).
- The same pair seen in both orders (a,b) and (b,a).
- Cancelled baskets and baskets outside the window.

## Constraints

- One read-only `SELECT` / `WITH` statement, PostgreSQL 17.
- Pairs per basket grow quadratically with basket size. Be ready to discuss what that means for
  a 500M-line fact table.

## Clarify before you code (what a strong candidate asks)

- Count baskets, units or revenue?
- Should (a, b) and (b, a) be one pair or two? Are self-pairs wanted?
- What is the minimum support, and is it absolute or a share of baskets?
- Is the basket a transaction, a customer-day, or a session?
