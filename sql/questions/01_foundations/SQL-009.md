# SQL-009 · Average completed transaction value by customer segment

**Topic:** foundations · **Level:** medium · **Interview time:** ~15 min · **Mode:** query

## Business context

The commercial team is setting 2026 targets per customer segment and needs a 2025 baseline:
how big is the average completed basket in each segment, and how much does an average customer of
the segment spend? A new **PILOT** segment was launched late in the year. It must appear in the
report even though nobody in it has completed a purchase yet, and the report must not crash or
show misleading numbers for it.

## Source tables

| table | grain | columns you need |
|---|---|---|
| `customers` | one row per registered customer | `customer_id`, `segment` (CONSUMER / SMALL_BUSINESS / ENTERPRISE / PILOT) |
| `transactions` | one row per checkout transaction | `customer_id` (NULL = guest), `transaction_ts` (UTC), `gross_amount`, `transaction_status` |

## Requirements

1. Use the customer's **current** `segment` from `customers`.
2. In scope: `COMPLETED` transactions with a UTC business date in 2025, i.e. `transaction_ts` in
   `[2025-01-01 00:00:00 UTC, 2026-01-01 00:00:00 UTC)`. Guest checkouts belong to no segment
   and are ignored.
3. Return **one row per segment that has at least one customer**, including segments with no
   in-scope transactions.
4. Metrics per segment:
   - `customers`: all customers of the segment (buyers and non-buyers).
   - `customers_without_purchases`: customers of the segment with zero in-scope transactions.
   - `completed_txn_count` and `total_completed_amount` (0 and 0.00 when there are none).
   - `avg_txn_value = total_completed_amount / completed_txn_count`, i.e. the average over
     **transactions**, so every transaction weighs the same no matter which customer made it.
     When the segment has no transactions this is **NULL** (undefined, not zero).
   - `avg_spend_per_customer = total_completed_amount / customers`. Non-buyers count in the
     denominator, so this is **0.00** for a segment where nobody bought.
5. Round both averages to **2 decimals**.

## Output contract

| column | type | notes |
|---|---|---|
| `segment` | text | |
| `customers` | integer | |
| `customers_without_purchases` | integer | |
| `completed_txn_count` | integer | 0 if none |
| `total_completed_amount` | numeric | 0.00 if none |
| `avg_txn_value` | numeric | 2 decimals; NULL when `completed_txn_count = 0` |
| `avg_spend_per_customer` | numeric | 2 decimals; 0.00 when nobody bought |

Ordering: none required (unordered set). Numbers are compared at 2 decimals.

## Illustrative example (not the real data)

Segment GOLD has customers 1, 2 and 3. Customer 1 completed purchases of 10.00 and 20.00,
customer 2 completed one of 90.00, customer 3 bought nothing.

| segment | customers | customers_without_purchases | completed_txn_count | total_completed_amount | avg_txn_value | avg_spend_per_customer |
|---|---|---|---|---|---|---|
| GOLD | 3 | 1 | 3 | 120.00 | 40.00 | 40.00 |

The average of the two buyers' own averages (15.00 and 90.00) would be 52.50, which is **not**
what is asked.

## Edge cases you must handle

- A segment where no customer has completed a purchase (some have only cancelled ones).
- Customers without any transaction.
- Very heavy customers that would dominate a per-customer average.
- Division by zero.

## Constraints

- One read-only `SELECT` / `WITH` statement, valid PostgreSQL 17.

## Clarify before you code (what a strong candidate asks)

- Current segment or the segment at the time of purchase?
- Average per transaction or per customer, and should non-buyers be in the denominator?
- NULL or 0 when an average is undefined?
- Should refunds reduce the basket value? (Not here.)
