# SQL-001 · Lifetime completed spend per customer, zeros included

**Topic:** foundations · **Level:** easy · **Interview time:** ~10 min · **Mode:** query

## In plain words

> "Give me every customer with how many purchases they completed and how much they spent in total. Customers who never bought still need a row, with zeros."

**You return:** one row per customer: `customer_id`, `completed_txn_count` (0 if none), `total_completed_spend` (0.00 if none).

**The fine print, in short:**
- Only **completed** transactions count. Pending, cancelled and declined ones add nothing.
- Use the whole history, and every customer whatever their status.
- Guest checkouts (no customer) never get a row.

## Business context

The CRM team is building a "customer value" attribute that will be loaded into the marketing
platform for **every registered customer**. Customers who have never completed a purchase must
still be present with an explicit zero, because the platform treats a missing value as
"unknown" and a missing row as "customer deleted".

## Source tables

| table | grain | columns you need |
|---|---|---|
| `customers` | one row per registered customer | `customer_id` |
| `transactions` | one row per checkout transaction | `customer_id` (NULL = guest), `gross_amount`, `transaction_status` |

## Requirements

1. Return **one row per row of `customers`**, all of them, regardless of customer status.
2. Only `transaction_status = 'COMPLETED'` transactions count. `PENDING`, `CANCELLED` and
   `DECLINED` transactions contribute nothing (neither to the count nor to the amount).
3. Spend is the sum of `transactions.gross_amount`. Use the whole history (no date filter).
4. A customer with no completed transaction gets `completed_txn_count = 0` and
   `total_completed_spend = 0.00` (**never NULL**).
5. Guest checkouts (`customer_id IS NULL`) are not customers and must not produce a row.

## Output contract

| column | type | notes |
|---|---|---|
| `customer_id` | integer | every customer exactly once |
| `completed_txn_count` | integer | number of completed transactions, 0 if none |
| `total_completed_spend` | numeric | sum of `gross_amount` of completed transactions, 0.00 if none |

Ordering: none required (rows are compared as an unordered set). Amounts are compared at 2 decimals.

## Illustrative example (not the real data)

| customer | transactions | completed_txn_count | total_completed_spend |
|---|---|---|---|
| 701 | COMPLETED 12.50, COMPLETED 7.50, PENDING 99.00 | 2 | 20.00 |
| 702 | CANCELLED 30.00 | 0 | 0.00 |
| 703 | none | 0 | 0.00 |

## Edge cases you must handle

- Customers with no transactions at all.
- Customers whose only transactions are not completed (cancelled, pending).
- Customers with a mix of completed and non-completed transactions.
- Guest transactions in the same table.

## Constraints

- One read-only `SELECT` / `WITH` statement, valid PostgreSQL 17.
- The production table has about 500 million transactions and 20 million customers; be ready to
  say how the query behaves at that size.

## Clarify before you code (what a strong candidate asks)

- Should closed or dormant customers be included?
- Do refunds reduce "spend" here? (No: that is a later exercise. Use `gross_amount` only.)
- Is "zero" `0`, `0.00` or NULL in the target system?
- Is the result a full snapshot or an incremental delta?
