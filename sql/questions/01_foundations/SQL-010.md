# SQL-010 · Bought product A but never product B

**Topic:** foundations · **Level:** medium · **Interview time:** ~15 min · **Mode:** query

## Business context

Customers who buy **Arabica Espresso Beans 1kg** (`product_id = 1`, "A") usually also buy the
**Milk Frother Wand** (`product_id = 2`, "B"). Marketing wants to send a cross-sell offer for B
to everyone who bought A in the first half of 2025 but did not buy B in that same period.

## Source tables

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction | `transaction_id`, `customer_id` (NULL = guest), `transaction_ts` (UTC), `transaction_status` |
| `transaction_items` | one row per order line | `transaction_id`, `product_id` |

## Requirements

1. A purchase of a product is a line of a `COMPLETED` transaction with a known customer and a UTC
   business date in `[2025-01-01, 2025-07-01)` (i.e. 2025-01-01 through 2025-06-30). The **same**
   definition applies to A and to B.
2. Return each customer who purchased A at least once **and** never purchased B, both judged
   under that definition.
   - B bought only in a cancelled, pending or declined transaction does not count as buying B.
   - B bought only outside the period does not count as buying B in the period.
   - Buying A and B in the same transaction counts as buying B.
3. Each customer appears once.

## Output contract

| column | type | notes |
|---|---|---|
| `customer_id` | integer | one row per qualifying customer |

Ordering: none required (unordered set).

## Illustrative example (not the real data)

| customer | in-period completed purchases | other | qualifies? |
|---|---|---|---|
| 901 | A, A | | yes |
| 902 | A + B on one receipt | | no |
| 903 | A | B in a CANCELLED order | yes |
| 904 | A | B in August 2025 | yes |
| 905 | | A in a CANCELLED order | no |

## Edge cases you must handle

- Several A purchases by the same customer.
- B purchases that do not satisfy the purchase definition (status, period).
- Guest checkouts that bought B.
- A and B in the same transaction.

## Constraints

- One read-only `SELECT` / `WITH` statement, valid PostgreSQL 17.
- Production has 1.2B order lines. Be ready to compare at least two ways to express "never".

## Clarify before you code (what a strong candidate asks)

- Is "never" limited to the same period, or all time?
- Does a cancelled or refunded purchase of B count?
- Should guests be considered (they cannot receive the offer)?
- What if the customer bought B before the period started?
