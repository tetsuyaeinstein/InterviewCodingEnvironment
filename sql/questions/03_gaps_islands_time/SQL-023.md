# SQL-023 · Longest purchase streak per customer with a deterministic tie-break

**Topic:** gaps, islands & time · **Level:** medium · **Interview time:** ~25 min · **Mode:** query

## Business context

For the 2025 year-in-review e-mail ("Your best streak this year: 6 days, 10 to 15 September"),
marketing needs exactly **one** best streak per customer. The e-mail job is re-run several
times, so the chosen streak must be **deterministic**: the same data must always produce the same
dates. Marketing also wants to know when a customer had several equally long best streaks, so the
copy can say "and you did it twice".

## Source table

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction | `customer_id`, `transaction_ts` (timestamptz, UTC), `transaction_status` |

## Definitions

- A **purchase day** is a UTC calendar date with at least one `COMPLETED` transaction of the
  customer (several purchases on one day = one purchase day).
- A **streak** is a maximal run of consecutive purchase days.
- Only purchase days **in calendar year 2025** (UTC dates 2025-01-01 … 2025-12-31) are considered.
  Days in 2024 do not exist for this report, so a run that began in December 2024 counts only
  from 2025-01-01.

## Requirements

1. Only `COMPLETED` transactions count; guests (`customer_id IS NULL`) are excluded.
2. For each customer, find their **longest** 2025 streak.
3. **Tie rule:** if several streaks share the maximum length, report the one with the
   **earliest start date**.
4. Report how many of the customer's 2025 streaks have that maximum length (`tied_streaks`,
   1 when there is no tie).
5. Return only customers whose longest streak is **at least 2 days**.

## Output contract

| column | type | notes |
|---|---|---|
| `customer_id` | integer | one row per customer |
| `longest_streak_days` | integer | length of the longest 2025 streak |
| `streak_start` | date | start of the chosen streak (inclusive) |
| `streak_end` | date | end of the chosen streak (inclusive) |
| `tied_streaks` | integer | number of 2025 streaks whose length = `longest_streak_days` (≥ 1) |

Ordering: none required.

## Illustrative example (not the real data)

| customer_id | completed purchase dates (UTC) |
|---|---|
| 801 | 2025: Apr 2, Apr 3, Apr 4, Aug 20, Aug 21, Aug 22 |
| 802 | 2024: Dec 30, Dec 31; 2025: Jan 1, Jan 2, Jul 9 |
| 803 | 2025: Mar 3, Mar 9, Mar 20 |

Expected output:

| customer_id | longest_streak_days | streak_start | streak_end | tied_streaks |
|---|---|---|---|---|
| 801 | 3 | 2025-04-02 | 2025-04-04 | 2 |
| 802 | 2 | 2025-01-01 | 2025-01-02 | 1 |

(803's longest streak is 1 day, so it is not returned.)

## Edge cases you must handle

- Two different streaks of the same maximum length → exactly one row with the earliest start,
  and the tie is counted.
- Several purchases per day; cancelled-only or pending-only days break a streak.
- A run crossing 2024-12-31 → 2025-01-01 is clipped at the year boundary.
- Customers whose purchases all fall outside 2025 do not appear.

## Constraints

- One read-only `SELECT` / `WITH` statement, PostgreSQL 17.
- Filter the year with a range predicate on `transaction_ts` that an index on that column could use.
- PostgreSQL date arithmetic only.

## Clarify before you code (what a strong candidate asks)

- Earliest, latest, or all tied streaks? (This spec: earliest start plus a tie count.)
- Is a streak running across the year boundary clipped or attributed to one year?
- Are single-day "streaks" interesting?
