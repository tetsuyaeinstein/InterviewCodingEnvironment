# SQL-024 · Five consecutive days with daily spend above 100

**Topic:** gaps, islands & time · **Level:** hard · **Interview time:** ~25 min · **Mode:** query

## In plain words

> "Which customers had five or more days in a row where they spent more than 100 a day? Show their earliest such run."

**You return:** one row per qualifying customer: `customer_id`, `run_start`, `run_end`, `run_days`.

**The fine print, in short:**
- Daily spend is the sum of **completed** transactions on that UTC date, no refunds, guests excluded. A big day is strictly over 100.00.
- Report the earliest qualifying run, at its full length (a 6-day run shows 6).
- Whole history, no date filter.

## Business context

The "Big Spender Week" promotion awards a badge to customers who spent **more than 100.00 on
each of five consecutive days**. Finance has been burned before by double counting and by
cancelled orders, so the rules below are strict. For every qualifying customer they want the
**first** qualifying run, so the badge can be dated.

## Source table

| table | grain | columns you need |
|---|---|---|
| `transactions` | one row per checkout transaction | `customer_id`, `transaction_ts` (timestamptz, UTC), `transaction_status`, `gross_amount` numeric(12,2) |

## Definitions

- **Daily spend** of a customer on a UTC date = the sum of `gross_amount` over that customer's
  `COMPLETED` transactions on that date. Refunds are ignored.
- A **big day** is a date whose daily spend is **strictly greater than 100.00**.
- A **run** is a maximal sequence of consecutive calendar dates that are all big days.

## Requirements

1. Only `COMPLETED` transactions count towards spend; guests are excluded.
2. A customer qualifies if they have at least one run of **5 or more** big days.
3. For each qualifying customer return their **earliest** qualifying run (smallest start date),
   with the run's full length: a 6-day run is reported as 6 days, not truncated to 5.
4. Whole data history, no date filter.

## Output contract

| column | type | notes |
|---|---|---|
| `customer_id` | integer | one row per qualifying customer |
| `run_start` | date | first day of the earliest qualifying run |
| `run_end` | date | last day of that run (inclusive) |
| `run_days` | integer | `run_end - run_start + 1` (≥ 5) |

Ordering: none required.

## Illustrative example (not the real data)

| customer_id | daily completed spend, Mar 1 … Mar 6 |
|---|---|
| 901 | 150, 101 (= 41 + 60), 200, 130, 100.50, 99.99 |
| 902 | 300, 300, 60 (+ a **cancelled** 300), 300, 300, 300 |
| 903 | 120, 130, 100.00, 140, 150, 160 |
| 904 | 99 every day (one purchase per day) |

Expected output: a single row `901 | Mar 1 | Mar 5 | 5`. Customer 902 fails on Mar 3 (the
cancelled order does not count), 903 fails on Mar 3 (exactly 100.00 is not more than 100.00),
and 904 never exceeds 100.00.

## Edge cases you must handle

- A day reaches the threshold only by adding up several smaller purchases.
- A daily total of exactly 100.00 does not qualify; 100.01 does.
- Cancelled amounts must not be counted, even if they would push a day over the threshold.
- Several qualifying runs → only the earliest is reported, once.

## Constraints

- One read-only `SELECT` / `WITH` statement, PostgreSQL 17. Exact `numeric` comparisons, no floats.
- Be ready to explain where the aggregation must happen relative to the streak logic, and why.

## Clarify before you code (what a strong candidate asks)

- Is the threshold on gross or on net-of-refund spend? Inclusive or exclusive?
- Is the day boundary UTC or store-local?
- Which run is reported if there are several, and is the badge dated on its first or fifth day?
