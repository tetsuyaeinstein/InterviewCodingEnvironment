## Hint 1
First reduce the log to one row per event: the first `LOADED` attempt. Only then compute anything. Percentiles over attempt rows would count retried and duplicated events several times.

## Hint 2
PostgreSQL has aggregates that take a sort specification inside `WITHIN GROUP (ORDER BY ...)`. One of them interpolates between neighbouring values, another returns an actual value from the data. Which one does the requirement describe?

## Hint 3
To exclude negative delays from the percentiles but still count them, aggregate with a `FILTER` clause (it also works on ordered-set aggregates) instead of deleting the rows in a WHERE. Convert the interval to seconds with `extract(epoch FROM ...)` and cast to `numeric` before `round(..., 2)`.
