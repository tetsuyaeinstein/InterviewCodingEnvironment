## Hint 1
Ask what the second run sees: the target already contains the first run's result. Any write that *adds to* what is stored cannot be idempotent. Your values must depend only on the batch.

## Hint 2
First reduce the batch to the current version of each transaction (highest `delivery_id`), then aggregate the completed ones by UTC date and store.

## Hint 3
The batch is complete per date, so treat each date as a partition you replace: remove the summary rows of exactly those dates, then insert the recomputed ones. (A `MERGE` that sets values, plus a scoped delete of rows that have no recomputed counterpart, works too.)
