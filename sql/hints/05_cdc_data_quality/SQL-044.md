## Hint 1
You need rows from both sides even when the other side has no match. Which join keeps unmatched rows from both tables?

## Hint 2
`a <> b` is NULL (not true) when either side is NULL, so fixture 90010 (NULL vs 1001) would slip through. PostgreSQL has a NULL-safe comparison operator for exactly this.

## Hint 3
Build the column list with one `CASE WHEN s.col IS DISTINCT FROM t.col THEN 'col' END` per column. `concat_ws(',', ...)` skips NULL arguments, so only the differing names remain. Report a matched key only if that list is non-empty.
