## Hint 1
Clip every in-scope incident to the January window first. After that it is a pure "merge intervals" problem per device; summing raw lengths over-counts every overlap and duplicate.

## Hint 2
Sort a device's intervals by start. An interval begins a new outage only if it starts strictly after the end of everything that came before it. Comparing only with the immediately previous row is not enough when an earlier interval is still open.

## Hint 3
The maximum `down_to` over all *preceding* rows (`ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING`) is the end of the current outage. Flag new outages, take a running sum of the flags as the outage id, then group to get each outage's min start and max end. PostgreSQL 14+ can also merge ranges for you with an aggregate over `tstzrange` values.
