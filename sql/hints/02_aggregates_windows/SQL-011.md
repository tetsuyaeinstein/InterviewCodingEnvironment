## Hint 1
Filter to completed, non-guest transactions first. Then think about a way to number each customer's transactions from newest to oldest.

## Hint 2
"Find the max timestamp, then join back to the table" returns two rows when two transactions share that timestamp. Your ordering needs a second key so that exactly one row is first.

## Hint 3
Number rows per customer ordered by timestamp descending, then id descending, and keep number 1 (filter in an outer query). PostgreSQL also has a one-row-per-key form of `SELECT DISTINCT` that relies on the same `ORDER BY`.
