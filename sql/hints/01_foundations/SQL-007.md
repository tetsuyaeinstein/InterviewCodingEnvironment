## Hint 1
For each staging row you need two facts: does the referenced transaction exist, and does the referenced product exist? Both parents are looked up by their primary key, so the lookup returns at most one match and cannot multiply staging rows.

## Hint 2
`x NOT IN (SELECT id FROM parent)` is a trap: when `x` is NULL the predicate is NULL, not true, so rows with NULL keys vanish silently. An outer join, or `EXISTS`, gives an unambiguous true/false answer.

## Hint 3
Test the NULL cases first, explicitly, then the missing cases. Order the `CASE` branches exactly like the precedence table, with the "both missing" branch before the single-missing ones.
